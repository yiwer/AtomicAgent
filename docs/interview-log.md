# AtomicAgent 需求访谈记录

## 第一轮：目标与硬约束

状态：用户已回答“自己的后端服务”“其他按推荐”。

### Q1 首批调用方

是自己的后端服务、组织内多个团队，还是可自行注册的外部开发者？

建议：先明确一个能直接观察使用效果的调用方群体；产品可以面向通用任务，但首期验收要有具体用户。

### Q2 代表性任务

提供最希望放大的 2–3 个真实 API 调用：每个调用提供什么输入、期望返回什么、现在单次 LLM 调用哪里做不到？

建议：至少覆盖一个“文件输入 → 处理后的文件与结构化结果”，再给一个真正需要的工具执行场景。任务不必是写代码；示例建议不构成范围限制。

### Q3 部署硬约束

必须本地、自有服务器、私有云，还是可以使用托管 sandbox？数据或模型供应商有无地域限制？

建议：接口设计保留自托管能力；实际首期部署依据硬约束和运维资源选择。

## 暂缓的问题

时延、任务期限、异步与同步协议、结果验证、持久状态、任意配置、外部副作用、生产隔离、首期引擎与工程规模，依赖本轮回答或正在收集的技术证据，不在本轮代替用户决定。

## 第二轮：任务边界

状态：已回答。用户原话：“考虑确定使用的coding agent设置为claude，方便我使用qwen token plan配置进行测试。两类都覆盖。首期外部只读。任务独立，API调用结束后直接清理。已登记配置＋按请求组合。”

- Q4：文件处理与资料研究两类具体样例是否均作为首批验收样例？推荐均覆盖，但不把通用平台做成专用应用。
- Q5：首期是否允许 sandbox 外部写操作？推荐外部只读，写入仅发生在本次 sandbox，产物由后端接收。
- Q6：两次请求是否自动继承状态？推荐任务独立，跨任务显式引用产物，不公开无限续接的会话。
- Q7：配置是否任意执行？推荐平台登记环境模板、Skills、MCP，后端按请求组合并传受约束参数，平台校验实际权限、资源和网络范围。

结果：Q4、Q5、Q7 按推荐确认；Q6 确认独立任务并增加调用结束清理要求。首期引擎直接由用户确定为 Claude，不再让多引擎抽象阻挡首期；Qwen Token Plan 的具体产品身份和使用边界研究中。

## 第三轮：调用结束和产物交付

状态：已回答。用户选择“任务可继续，任务终态后清理”“产物转存并保留 24 小时”。

- Q8：客户端断连或网关超时是否必须结束任务？推荐同步／流式响应，断连或执行期限到达即取消，短暂终止宽限期后强制回收；不提供后台继续执行。保留任务身份用于查询清理状态。
- Q9：sandbox 清理后的产物交付方式？推荐结果 JSON 随响应返回，文件先转存、返回下载引用，默认保留 24 小时；输入暂存、工作目录和 agent 会话随执行空间清理。

本轮建议基于用户新增的调用结束清理要求，不把前期研究报告中的“持久 Run、断连继续执行”候选建议当作已批准架构。

结果：用户明确选择断连后继续，因此第三轮关于断连即取消的建议被否决；应保持任务运行直到完成、失败、超时或显式取消，终态后清理 sandbox。产物独立转存并保留 24 小时。

## 第四轮：对外合约与验证方向

状态：Q10–Q13 已回答；Q14 改为先比较 OpenSandbox 与 Sandcastle，再决定。

- Q10：推荐固定 Claude Code／Agent SDK，模型供应商连接作为独立登记配置；Qwen 按量 API 作为待验证候选，不将 Token Plan 当作必需依赖。当前 Token Plan 官方 FAQ 排除后端自动化用途，具体证据另见专项报告；不购买或实际调用服务。
- Q11：推荐持久 Run、可等待结果、查询、SSE、显式取消、提交幂等；首期不做 webhook 或 OpenAI Chat Completions 兼容层。
- Q12：推荐结构化结果、摘要、产物清单、用量；schema 与必需产物转存验证通过后才成功，任务专属断言另行验收；缺失必须的输入或授权时失败，不等待人工交互。
- Q13：推荐可调实验上限为并发 2、任务总期限 15 分钟、输入总量 50 MiB、产物总量 100 MiB、每 sandbox 2 vCPU／4 GiB。它们不是生产 SLA 或供应商能力保证；模型预算由接入证据决定。
- Q14：推荐 Linux + OpenSandbox，先验证 Docker 路径并评估 gVisor，平台采用持久任务数据库、worker、产物存储；Kubernetes、Temporal、多引擎编排不作为首期前置。

用户回复：固定 Claude Code／Agent SDK；接受任务 API 与完成标准；接受可调实验上限；要求对比 OpenSandbox 和 `https://github.com/mattpocock/sandcastle`，允许子代理比较。没有将“使用 Qwen 按量 API”明确批准为已变更的具体模型配置；精确模型 profile 保持待验证。

## 第五轮：失败、输入配置与记录保留

日期：2026-09-13（用户更新当前日期）。状态：用户回复“全部按推荐”，以下均已确认。

- Q15：对环境创建、短暂模型错误、产物上传等明确阶段做有界重试；Agent 已执行后的整项任务不自动重跑。Worker 失联先查原执行，无法安全接管则终止并返回明确错误；业务重做创建新任务，相同幂等键只找回旧任务。
- Q16：环境、Skills、MCP、模型连接以版本化清单登记，不做首期管理后台；密钥通过服务端 secret 引用。请求传提示词、已上传文件或前次产物引用、配置 ID 与受约束参数；必需配置加载失败即明确失败。
- Q17：状态、结果 JSON、产物清单、脱敏事件、幂等记录保留 7 天；输出文件保留 24 小时，过期后明确标记不可下载。默认不长期保存完整提示词、输入正文、原始模型对话；失败任务也清理执行空间。

下一步：源码对比 OpenSandbox／Sandcastle，给出与已确认需求相符的底座建议。真实 Qwen 接入和隔离/性能实验属于尚未执行的验证事项，不将其当成已经通过。

## 第六轮：底座选型与合约默认值

日期：2026-09-13。状态：已回答。用户回复“按你的推荐”，随后补充“时间可以更宽泛一些”。依据 [固定版本源码对比](research/05-opensandbox-vs-sandcastle.md)。

- Q18：推荐 OpenSandbox 作为执行空间底座，直接使用 Claude Agent SDK，首期不叠加 Sandcastle；Sandcastle 保留为 Git/worktree/多 Agent 编排参考。用户已接受。
- Q19：推荐可配置默认值：提交等待至多 30 秒后返回 Run；显式取消给 10 秒退出宽限；终态立即触发回收，60 秒内清理完成为待实测目标；可重试阶段最多追加 2 次重试；默认不让 Agent 自动修复不合格结果；未使用上传暂存 24 小时；结果/产物保留期从终态提交开始。15 分钟任务总期限保持已确认值。

该轮只决定设计，不部署 sandbox、不读取密钥、不运行计费模型；实测目标不能当作已经实现的保证。

时间修订：根据用户放宽时间的方向，将任务默认总期限从 15 分钟调整为 60 分钟，取消宽限从 10 秒调整为 30 秒，清理目标从 60 秒调整为 5 分钟。以上仍可配置且需实测；HTTP 提交等待 30 秒后返回 Run，可继续执行。其余默认规则按推荐采用。
