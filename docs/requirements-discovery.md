## 用户已表达的目标

- 提供一个 Agent 运行时接口能力平台，复用 Codex、Claude、Pi 等 coding agent 的执行能力。
- 调用方通过一次 API 请求描述任务；平台启动 sandbox、装载 coding agent、执行任务，通过约定协议获取结果并返回给调用方。
- 请求应支持提示词、初始文件、环境配置、Skills 配置和 MCP 配置。
- 希望放大单次 LLM 调用的能力；当前未将任务限定为代码生成或软件开发。
- 当前阶段是需求分析、需求挖掘和开源技术研究。

## 尚未成立的假设

- “一次 API 请求”是一次任务提交；连接断开后允许任务继续。具体等待、查询和事件接口在第四轮确认。
- “启动一个 sandbox”是否要求每次创建新的物理实例，还是要求每次有独立、干净的执行空间，尚未确认。
- 首期固定 Claude；是否在以后支持多引擎，以及任意任务的能力边界，尚未确认。
- 部署地点、时延、并发、预算与结果验收标准尚未确认。首批调用方为自有后端，首期禁止外部写操作。
- 当前没有既有实现可作为行为依据；工作目录初始为空，尚不是 Git 仓库。

## 待检验的领域区分

以下只是访谈候选，尚未写入正式术语表：

| 候选概念 | 需要明确的边界 |
| --- | --- |
| 运行请求 | 调用方声明的目标、输入、配置和限制；是否有稳定的请求身份？ |
| 任务运行（Run） | 是否独立于一次 HTTP 连接存在？是否可以包含多次执行尝试？ |
| 执行尝试（Attempt） | 一个失败后的重试是否创建新尝试？哪些输入和副作用可以复用？ |
| Agent 会话（Session） | 是引擎内部对话历史，还是对调用方公开、可以继续的业务对象？ |
| 执行空间 | 本次任务可访问的文件与进程环境；是否与实际 sandbox 实例一一对应？ |
| 执行配置 | 引擎、环境、Skills、MCP、网络和工具能力的请求声明；何者实际获准？ |
| 任务结果 | 可被调用方消费和验证的最终输出；与最后一条聊天消息是否相同？ |
| 任务产物 | 需返回或保留的文件；身份、大小、保留时间、下载权限如何确定？ |

## 场景探针

这些场景用来暴露边界，不是已加入首期的功能清单。

1. Agent 输出符合 JSON Schema，但引用了不存在的文件。平台能宣告成功吗？
2. Agent 已完成外部写操作，返回结果前进程退出。自动重试会不会重复写入？
3. 调用方等待超时后用相同业务请求再次提交。平台应返回原任务还是执行新任务？
4. 两个请求使用相同 Skills 和环境，但带有不同凭据。哪些内容可以缓存或复用？
5. 调用方提供的 MCP server 需要启动脚本和访问公网。它运行在哪个隔离边界内？
6. 客户端断开事件流后任务继续运行，稍后取消到达。已经发生的操作如何报告？
7. Agent 自述“完成”，但执行测试失败、产物缺失或预算耗尽。哪一方有最终完成判定权？
8. 相同任务分别用 Codex、Claude、Pi 执行，某引擎没有对应能力。请求应拒绝、降级还是暴露差异？

## 输入能力背后的产品合约

用户已提出左列能力；右列是需求分析推导出的待确定事项，不是自动增加的已批准功能。

| API 能力 | 调用方需要知道的合约 | 平台需要解决的问题 |
| --- | --- | --- |
| 提示词 | 目标、限制、输出要求分别是什么？ | 用户任务与平台权限规则冲突时，哪些规则仍不可越过？ |
| 初始文件 | 来源、目录、体积、可写性、编码；能否引用上次产物？ | 导入失败、路径逃逸、同名覆盖、压缩包展开与输入完整性 |
| 环境配置 | 运行语言、依赖、系统工具与资源配额 | 环境准备失败与任务失败分开；环境身份与复用范围 |
| Skills | 如何选择、固定版本、声明依赖？ | Skills 不只是文本，也可能携带脚本；加载成功需要证据 |
| MCP | 选择哪些服务、哪些工具、传什么参数？ | 本地进程与远程服务边界、凭据、网络权限及工具副作用 |
| Coding agent | 调用方是否指定引擎与版本？ | 能力不齐时明确拒绝或暴露差异，避免静默忽略配置 |
| 返回结果 | 文本、JSON、产物和执行摘要如何区分？ | 校验后再宣告成功；文件存在且已持久化，才承诺可下载 |

## 候选验收方法

以下测试对象是平台自身的行为；结果质量还需要由 Q4 的具体任务断言定义。

| 故障／行为 | 应当观察的事实 | 待确定的产品规则 |
| --- | --- | --- |
| 一个请求被客户端重复提交 | 是否产生重复任务与重复费用 | 请求幂等键的范围与有效期 |
| 下载初始文件失败 | 是否启动了 agent；最终错误类型 | 是否可重试，重试是否消耗执行预算 |
| 指定 Skill 或 MCP 无法加载 | 实际加载记录与最终状态 | 明确失败还是允许显式声明的可选能力缺失 |
| Agent 正常退出但结果格式错误 | 引擎结束事件与平台验证失败各自可见 | 是否允许有预算的结果修复 |
| 文件已生成但上传失败 | sandbox 内文件与对外产物清单不混淆 | 只重试产物收集还是重跑任务 |
| 客户端断连 | 任务是否继续、重连能否补读结果 | 任务生命周期是否独立于连接 |
| 超时或取消 | 最后可观测状态、子进程是否停止、资源何时释放 | 最终状态与取消竞争时如何裁定 |
| Worker 被终止 | 是否遗留任务、sandbox、凭据与费用 | 如何发现失联并恢复或终止 |
| CPU、内存、输出或模型预算耗尽 | 明确的限额事件和部分结果可用性 | 硬限制与事后统计如何区分 |
| 不同任务读取彼此的文件 | 访问是否被隔离策略拒绝 | 逻辑独立和物理隔离的最低要求 |

候选质量维度：业务成功率、结构化结果合格率、产物完整率、任务总时延、环境准备时延、单位成功任务成本、失联资源清理时长。先定义测量方式，再依代表性任务和部署实测确定目标值；不借用开源项目宣传数字作为本平台验收结果。
