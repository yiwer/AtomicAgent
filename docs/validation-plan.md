# AtomicAgent 首期验证计划

更新：2026-09-13。状态：需求阶段的候选验收材料，尚未执行。每条结果需要区分替身故障实验、真实 runtime／模型实验和部署隔离验收，不将任何一种替代其他证据。

## 1. 文件处理样例

以下是人为构造的验收数据，不是用户真实业务数据。

```csv
id,category,value
r01,alpha,10
r02,beta,20
r03,alpha,15
r04,beta,invalid
r05,alpha,-5
r06,beta,0
r07,alpha,2.5
r08,beta,7.5
```

请求规则：按十进制数处理 `value`；负数和零有效，非数字行进入拒绝清单；保持输入顺序，输出有效数据 CSV、拒绝行 JSON，以及结构化统计。

确定断言：输入 8 行，有效 7 行，拒绝 1 行；拒绝行 ID 为 `r04`；总和 `50`，alpha 总和 `22.5`，beta 总和 `27.5`。必需产物为 `output/valid.csv` 和 `output/rejected.json`，结果 JSON 应携带对应计数与分组统计。

这个样例需要实际发生文件读取、代码执行和文件写入；只在聊天中给出正确数字不能验收“sandbox 文件处理”。另用同一模板装载一项登记 Skill，核对其可调用状态；若任务声明必须使用该 Skill，记录实际调用证据。

## 2. 资料研究样例

输入一个明确比较问题和允许使用的第一方来源，例如“比较两个项目的定位、Git 依赖和清理行为”。平台通过已登记只读搜索/抓取 MCP 获取材料，返回报告文件与包含来源 URL、获取时间、事实/推断区分的结构化结论。

验证分两层：

- **固定材料验收**：使用已保存且有摘要的官方源码/文档快照，准备可人工核对的事实清单；检查每条结论与实际材料对应。它验证推理和引用组织，不能代表实时网络访问已通过。
- **真实网络验收**：在获准模型连接下实际访问同一组第一方 URL，记录工具调用、HTTP 结果和来源身份；检查引用确实来自本次获取材料，允许内容变化时明确报告变化。

不能要求模型从一个 README 推导整个项目生产可靠性；缺少证据必须标为未知。报告格式合格、引用 URL 存在和结论正确需要分别记录。

## 3. 两类样例都必须经过的完整链路

`提交并保存 Run → 准备 sandbox → 装载输入与配置 → Claude 执行 → 校验输出 → 转存产物 → 提交终态 → 回收 sandbox → 取回结果与文件`

需记录 Run、Attempt、sandbox 身份以及固定 CLI/SDK/镜像/模型/配置版本。查询终态、产物清单和实际资源列表应该互相吻合。

## 4. 平台故障矩阵

| 实验 | 期望观察的行为 |
| --- | --- |
| 并发提交相同幂等 key | 一个逻辑 Run；重复调用得到相同身份，不重复启动 agent |
| 接受任务后响应丢失 | 用原 key 或已知 Run 找回执行；不自动新建任务 |
| SSE 断连 | 任务继续；重连按游标补读，查询得到同一权威状态 |
| Worker 重启 | 核对既有执行后恢复观察；不能安全接管则终止并明确失败 |
| sandbox 创建响应丢失 | 按资源身份/请求标签对账，不留下无人识别的执行环境 |
| 必需 MCP/Skill 初始化失败 | 明确准备失败，不能忽略缺失能力继续返回成功 |
| 模型短暂限流 | 阶段内有界退避，总期限和累计预算不重置 |
| Agent 声称完成但缺 JSON/文件 | 输出验证失败，不能提交成功 |
| 产物上传失败或上传后提交失败 | 恢复该阶段，不重新运行 Agent |
| 显式取消与完成竞争 | 只有一个权威终态；已提交成功不被迟到取消覆盖 |
| 超过总期限/资源上限 | 执行层实际限制或终止，错误指出限制维度 |
| 回收请求失败 | 结果与清理状态分开；后台继续回收并可观察，不重做业务 |
| 产物 24 小时后过期 | JSON/清单仍在 7 天保留窗口，文件明确不可下载，不触发重跑 |

## 5. 执行边界

- A 任务写入标记、启动子进程；A 终态后 B 使用相同环境模板，不能读取 A 文件、配置、凭据或继承进程。
- 验证只读 MCP 的真实授权；仅有工具注解或提示词说明不够。
- 验证网络出口与文件装载限制，包括符号链接、路径越界、重定向和不允许的目的地。
- 资源限制需要在选定 backend 实际触发；未暴露的参数不能用配置文件里出现了数字代替生效证据。
- 普通 Docker 的内部功能实验不能自动升级为 gVisor 或 microVM 的隔离验收。

## 6. 测量与报告

以已接受的并发 2 和文件/计算限额为起点；按用户放宽时间的要求，任务默认总期限调整为 60 分钟，取消宽限 30 秒，终态清理 5 分钟内完成作为待实测目标。拆分记录排队、准备、Agent/模型、产物提交和清理耗时；报告样本数、失败分类、单位成功任务的用量与可核实成本。

不预设实际成功率或 p95；先取得有代表性的重复测量，再建议生产目标。真实计费实验的账户和预算在实施阶段确定，本次没有调用付费服务。

## 7. 审计与监控闭环验收

在功能链路之外执行 [V-AO-01 至 V-AO-12](audit-monitoring.md)；每项需要实际查询结果、观测来源和故障注入证据。重点包括：

- 重复提交/SSE 不重复计数；实际配置修订、主体、拒绝和结果责任可查。
- Agent 伪造的审计/成功文本不能进入权威事实；trace 关闭不丢关键操作审计。
- 外部遥测故障和核心记录故障分别退化；停止/清理通路不能与日志出口一起失效。
- 删除失败、资源查询无权限、worker 失联均保留未知/未完成责任，不以 API 返回或日志文字宣告回收。
- 模型增量/累计/重试用量不重复计算，未知不显示零；敏感字段不能泄漏到任何观测出口。
- 文件过期访问阻断与物理删除分别核验；常规记录到期删除，未结束回收仅保留最小处置记录，核验完成后 7 天删除，按已接受 ADR 0006 测试。
- 告警从检测、归属、通知、确认到恢复均有证据；确认不当恢复，采集器失联不能自动消警。

告警投递以受控接收端先验证重试和失败语义；正式通道、接收者以及端到端试发在部署时单独配置并验证。当前没有真实告警投递或生产验收结果。
