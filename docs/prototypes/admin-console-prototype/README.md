# AtomicAgent 管理台 UI 原型 — THROWAWAY

日期：2026-09-13。状态：用户明确回复“选择A”，已选定 A「运维总览」作为 Web 管理台设计方向。原型仍使用内存模拟数据，设计选择不等于真实系统验收。

2026-09-14 后续：用户接受 v0＋A 的 33 张 tracer-bullet 拆分，正式范围见 [PRD](../../PRD-v0.md)，逐票入口见 [已发布计划](../../../.scratch/v0/ticket-plan.md)。以下探索与验证记录描述原型制作时状态；其中“范围待定／tracker 未配置”已由该批准与发布更新。模拟代码和归档仍保持原样，不作为已实现产品。

## 已选设计

- **整体结构**：固定左侧导航、顶部工作区与身份入口、中央工作内容。
- **首页层级**：运行与回收指标 → 待处置异常 → 任务表格；右侧提供依赖健康与最近操作。
- **导航分组**：任务／调度／sandbox 运行管理，配置／Skills／MCP／权限／额度／功能管理，异常／回收／审计。
- **详情与操作**：任务和配置通过详情面板展开；发布修订先展示变更摘要与影响范围。
- **状态表达**：任务成功、资源已回收、健康未知保持独立；取消、停用、撤销和回收分别操作。

选择依据：用户对三方案原型明确选择 A，未另述理由；以上记录 A 的具体设计特征，不推断用户批准了所有模拟控件或后端实现。B／C 保留为比较证据，后续正式管理台使用 A 的整体结构。

## 要回答的问题

同一平台如何组织监控、任务调度、版本化能力配置、权限、额度和回收处置，才能让维护者看清“当前事实、变更影响、下一步动作”？

用户明确新增 Web 管理系统探索。原项目只有设计文档，没有可承载的既有页面或前端框架，因此采用 prototype 技能的 UI 新页面分支，以无依赖 HTML／CSS／JavaScript 构建三个结构不同的方案。所有页面使用同一份内存演示状态，不接真实 backend。

## 启动

在项目根目录运行：

```powershell
python docs/prototypes/admin-console-prototype/serve.py
```

打开 [管理台原型](http://127.0.0.1:8765/?variant=A)。服务只绑定本机，Ctrl+C 停止；环境标为 production 时拒绝启动。

也可直接用浏览器打开同目录 [index.html](index.html)，无外部字体、CDN、软件安装或远程数据依赖。

底部按钮或键盘左右方向键切换方案；输入框、下拉框、文本编辑和弹窗内不拦截方向键。URL 的 variant 与 page 参数可分享，切换保留当前内存状态，刷新全部重置。

页底“查看完整模拟状态”展示全部相关状态；切换方案也将状态输出到浏览器控制台。两者用于解释原型，不是未来产品的强制入口。

## 可以体验的流程

1. **配置发布**：配置登记 → 环境／模型／Skills／MCP → 创建新修订 → 填写变更说明 → 核对摘要 → 发布演示修订。已有任务的配置引用保留原版本；配置详情可查看历史及影响范围。
2. **Skills 初始仓库**：查看来源、固定修订和入口；模拟发现候选后进入修订审查，不自动发布或注入运行任务。所有仓库 URL 是 example.invalid 演示地址。
3. **MCP 管理**：查看传输、只读工具名单与 secret 引用；模拟连接检查或创建新修订。结果不代表实际连接与授权已验证。
4. **能力组合**：选择固定环境／模型／Skill／MCP 版本并登记组合；提交演示任务时选择组合。停用的配置使新任务提交被拒绝。
5. **调度**：提交任务进入队列 → 调整队首／暂停调度 → 任务详情模拟完成或停止释放槽位 → 模拟调度下一项。排队中取消不产生 Attempt 或 sandbox。
6. **资源回收**：查看成功但回收逾期的 run_0840 → 确认接手 → 请求回收（核验中）→ 注入回收成功观测。只有最后一步模拟实际证据，业务成功状态不变。
7. **额度与功能**：编辑并发、总期限、文件限额、CPU／内存；切换文件／研究／产物引用等功能。每日 token 预警与修复开关是管理台探索，不是已验证的消费硬限制。
8. **权限**：以维护者调整演示角色能力，再通过右上角切换只读观察者或审计读取者；受限按钮不可用，审计读取单独授权。前端模拟不构成真实鉴权。
9. **故障退化**：异常演练 → 核心记录不可写，新接纳／配置发布／新执行阻断，停止和回收仍可用；采集失联时资源显示未知，不自动消警。恢复后再核验资源。
10. **审计与告警**：管理动作追加模拟操作记录，可导出演示 JSON；异常确认不恢复，抑制 15 分钟可通过演练的时间推进解除。未连接通知渠道。

## 领域边界与新增探索

沿用已确认术语：Run、Attempt、ConfigurationRevision、ExecutionManifest、CapabilityGrant、SandboxAllocation、CleanupObligation、AuditRecord 和 OperationalIncident。

配置停用与运行中授权撤销是不同命令；取消意图、实际停止和资源回收是不同事实。Result 成功、文件可用和资源不存在分别表达。核心记录故障的退化与最小回收责任沿用 accepted ADR 0006。

管理台是原 v0 “无管理后台”的显式新增需求探索，尚未决定纳入哪一版本。原型新提出的能力组合管理、人工调整队列、每日 token 预警、角色权限编辑和功能开关需在体验后细化为正式需求；现有基线不因页面上出现控件就自动获得实现承诺。

调度暂取“观察队列、人工优先、暂停／恢复新调度”，没有擅自加入周期任务、cron、多节点复杂调度或自动整项任务重跑。模型 profile 保持待验证，不把 Qwen Token Plan 自动切换成其他套餐。

## 验证记录

- JavaScript 语法检查通过；本地 HTTP 返回 200。
- 用 Node VM 的最小 DOM 替身执行三个方案、十二个页面的渲染函数，36 个组合均完成 HTML 生成。
- 检查模拟状态变化：取消后仍待停止核验、停止后资源仍待回收、调度遵守槽位、确认不消警、回收请求不宣告完成、陈旧观测阻止回收核验、核心记录故障阻止新执行而保留回收、发布新修订保留旧任务引用、只读角色无法管理配置。
- **未完成真实浏览器视觉和点击验收**：CUA 返回没有可用浏览器，无法取得截图或检查实际桌面／手机排版。上述检查不替代浏览器验收。
- 没有后端、持久化、真实权限、模型／MCP／仓库连接、sandbox 调度、产物存储或通知投递。不将 UI 原型当作产品实现或运行验收。
