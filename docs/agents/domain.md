# Domain Docs

单一 AtomicAgent 领域，划分任务执行、输出交付、资源回收、运行保障四组职责，不拆限界上下文。工程入口只用于开发协作，不作为任务 sandbox 的配置来源。

## 开始任务前

1. **术语** — [CONTEXT](../../CONTEXT.md)。用表里的名字，不用 _Avoid_ 排除的同义词。
2. **不变量** — [领域模型](../domain-model.md) 的 DM-01–12 与对象关系。实现必须同时满足它们；先违反、留给后票补是不允许的。
3. **决策** — [docs/adr/](../adr/)，0001–0006 全部 accepted，每份不到 20 行。与之冲突时显式修订，不由实现静默覆盖。
4. **需求正文** — [v0 PRD](../PRD-v0.md)：72 条故事、AC-01–28、A-AC-01–12。[票务计划](../../.scratch/v0/ticket-plan.md) 给出已批准范围、依赖与覆盖图；逐票文件拥有实施验收细节。

## Tracer bullet 交付

每票打通一个用户可观察的行为：入口 → 领域裁定 → 可靠持久化 → 实际执行／存储／资源边界 → 返回与页面 → 行为验证。该行为的权限、失败与重复请求处理、所属审计事件、带新鲜度的健康来源随它一起交付，不留到后续票。

结果和未知状态用领域术语表达。证据按 [证据分账](evidence.md) 的九类分别记录；原型只提供交互证据，未验证项保持未完成。
