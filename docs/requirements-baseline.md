# AtomicAgent 需求基线

更新：2026-09-13。状态：共同理解已确认。用户明确回复“确认 共同理解”，本轮需求挖掘完成；本文作为后续设计、兼容性实验与实施验收的需求基线。

## 1. 产品目标

让自有后端通过一次任务提交，使用 Claude Code／Agent SDK 在独立 sandbox 中完成多轮推理、文件处理和工具执行，得到可校验的结构化结果与文件产物。

“单次”表示一次独立业务任务，不限制内部模型调用轮数，也不要求同一条 HTTP 连接一直存活。首期同时覆盖文件处理和资料研究，保持通用的任务配置接口。

## 2. 首期边界

| 事项 | 已确认要求 |
| --- | --- |
| 调用方 | 自有后端服务 |
| 引擎 | Claude Code／Claude Agent SDK |
| 任务状态 | 各任务独立，不自动继承对话、文件或进程；需要复用产物时显式传入引用 |
| 外部权限 | 外部业务资源只读；任务内可写文件 |
| 配置 | 版本化登记清单，按请求选择环境、Skills、MCP、模型连接及受约束参数 |
| 交互 | 无人值守；必须补充输入或授权时明确失败，不挂起等人 |
| 生命周期 | 客户端断连后继续；任务终态后清理 sandbox |
| 交付 | 结果 JSON、摘要、产物清单、用量；必需产物转存后才成功 |
| 保留 | 文件产物 24 小时；任务状态、JSON 结果、清单、脱敏事件、幂等记录 7 天 |

首期不包含：持久交互会话、外部业务写操作、任意宿主启动配置、管理后台、多引擎编排、webhook、OpenAI Chat Completions 兼容层。

## 3. 请求输入

任务请求至少表达：

- **任务提示词**：描述目标、输入解释和输出要求。
- **初始文件**：引用已上传文件或前次未过期产物，并声明在任务内的相对路径；不引用宿主机任意路径。
- **环境配置**：选择已登记环境与版本，传入允许覆盖的参数和限额。
- **Skills**：选择已登记版本；平台需要证明成功加载，不能只证明文件已复制。
- **MCP**：选择已登记连接、只读工具权限及受约束参数；必需服务初始化失败时任务失败。
- **模型连接**：使用独立于 Claude runtime 的登记配置；secret 由服务端解析，请求不传密钥正文。
- **输出要求**：结构化结果约束和必需文件要求；不以默认自由文本替代明确输出契约。

用户最初希望用 Qwen Token Plan 测试。当前研究发现套餐用途限制与非 Claude 模型支持边界；具体 Qwen profile 仍需验证，不自动切换用户套餐、endpoint 或模型。详见 [专项报告](research/04-claude-qwen-compatibility.md)。

## 4. 对外任务 API

- 提交任务返回 `run_id`，支持等待终态或之后查询结果。
- 查询任务得到权威状态与已提交结果；SSE 提供可恢复的进度观察。
- HTTP 超时、断连不自动取消任务；显式取消接口请求停止任务。
- 提交支持幂等：相同调用方、相同 key、相同提交内容找回原 Run；相同 key、不同内容返回冲突。
- 新业务重做使用新任务身份。不能因为产物已过期、上次失败或客户端没收到响应，就把相同 key 静默当成新任务。
- 记录保留期届满后的幂等保证不延续；确切过期响应和事件格式见待定稿 API 合约。

## 5. 完成判定

只有结构化结果符合声明的 schema、必需产物存在并已转存、结果清单已提交，平台才返回成功。Agent 正常退出或声称完成不独自构成成功。

文件处理需要用明确的数据断言验证输出；研究报告需要来源信息及结论与来源的关联。平台的机械校验不承诺开放研究结论全部正确。

非成功结果需要区分配置/准备错误、执行错误、输出不合格、期限或资源耗尽、取消和产物交付失败。可留诊断摘要，但不能用半成品冒充成功结果。

## 6. 重试、失联与清理

- 只对明确阶段做有界重试，并计入本任务累计期限和预算。
- Agent 执行后的整项任务不自动重跑；重新执行由调用后端显式创建新任务。
- Worker 失联先核对已有执行身份；能否接管必须有证据。不能确认安全接管时，终止原执行并返回明确错误。
- 创建 sandbox 的响应丢失时，先查既有资源，不能无条件重复创建。
- 上传或结果提交失败时恢复相应阶段，避免重新运行 agent。
- 成功、失败、取消和超时均触发执行空间清理；清理失败保持独立状态并继续回收，不能改变已提交业务结果或触发业务重做。
- 清理包括任务进程、工作目录、临时配置与会话材料；保留策略允许的结果和诊断信息先移到执行空间之外。

## 7. 数据保留

| 数据 | 当前保留规则 |
| --- | --- |
| 已转存的输出文件 | 24 小时，到期不可下载，清单明确过期 |
| 状态、结果 JSON、产物清单、脱敏事件、幂等记录 | 7 天 |
| 完整提示词、输入正文、原始模型对话 | 默认不长期保存；工作副本随任务清理 |
| sandbox、运行进程、临时配置、Agent 会话 | 任务终态后清理 |

输出 JSON 本身可能含业务内容，7 天保留需要按调用方权限控制。下载引用的有效性与文件保留期不同：链接过期可以重新申请，文件删除后不能恢复下载。

## 8. 已接受的实验起点

| 项目 | 可调上限 |
| --- | --- |
| 并发运行任务 | 2 |
| 每任务默认总期限 | 60 分钟，可按登记配置调整 |
| 初始文件总量 | 50 MiB |
| 产物总量 | 100 MiB |
| 每 sandbox 计算资源 | 2 vCPU、4 GiB RAM |

这些是实验配置，不是生产 SLA、供应商保证或实测容量。模型预算必须以实际接入可计量、可执行的限制定义；不把 Claude 成本估算当作 Qwen 真实账单。

按用户“时间可以更宽泛一些”的要求，显式取消宽限调整为 30 秒，终态立即清理、5 分钟内完成作为待实测目标；HTTP 提交等待仍最多 30 秒，随后返回 Run 身份并继续执行。可重试阶段最多追加 2 次重试，默认关闭 Agent 结果修复。未使用上传暂存 24 小时；结果和产物保留期从终态提交起算。

## 9. 首批验收样例

### 文件处理

输入 CSV/JSON 和处理规则，利用代码完成变换或统计，返回处理后文件、统计 JSON 与摘要。验收包含可独立算出的统计值、必需行列与输出格式、配置加载、产物转存及销毁后可下载。

### 资料研究

输入研究问题和允许访问的数据源/只读 MCP，返回 Markdown 报告、结构化结论与来源信息。验收包含真实来源可取回、结论与来源对应、MCP 加载与权限生效、报告产物可下载；不得以格式检查代替内容核对。

两类验收都要经过真实 Claude runtime 和选定模型连接。固定替身只用于故障注入和边界测试，不能冒充真实模型执行证据。

## 10. 已选底座与待验证事项

- **Sandbox 底座**：用户已接受 OpenSandbox + Claude Agent SDK；首期不叠加 Sandcastle。推荐从独立 Linux 节点的 Docker 路径验证，再用同一工作负载评估 gVisor；不以前置 Kubernetes、Temporal 或多引擎编排扩大首期。
- **实际模型 profile**：精确供应商、endpoint、模型、凭据来源及允许用途需核实；不读取用户密钥来做需求研究。
- **固定发行版本兼容性**：Claude SDK/CLI、Qwen schema 与工具循环、Skills/MCP 加载、取消和进程回收需要实验。
- **实际性能和运行限制**：待完整任务和故障实验后给出测量结果。

用户已确认本文所表达的共同理解；后续工作以此基线推进兼容性实验与实施规格。此次确认是需求确认，不是 SDK/模型兼容性、生产隔离或性能的验收证据。

## 11. 领域模型、审计与运行监控补充

2026-09-13 用户进一步要求完善领域建模并检查审计、监控完整性，随后明确“新增策略确认使用建议”。本节及 [ADR 0006](adr/0006-audit-and-observation-boundaries.md) 纳入已确认基线：核心记录不可写时停止新任务、新授权和新执行，保留停止与回收通路；常规数据按期删除，未完成回收仅保留最小定位与责任，核验完成后再保留 7 天删除。此例外不延长业务正文或原始会话保留期。

- 将执行清单、任务授权、实际 Agent Attempt、资源占用、输出验收、用量条目和资源回收责任分开；详细归属与不变量见 [领域模型](domain-model.md)。
- 操作审计独立于 SSE、指标和诊断日志。关键记录包含可信主体、动作、对象、授权/配置版本、结果证据、时间与因果关联，拒绝和未知结果同样可查。
- 审计覆盖接纳/幂等、配置登记/停用、加载与调用、取消/验收/提交、结果访问、资源回收及运维处置。不可见的调用标为覆盖不足，不声称完整 Agent 行为回放。
- 监控覆盖 API、排队、阶段推进、worker 存活、实际资源、模型/MCP、用量、产物到期、回收和观测链自身健康；空闲、零资源和失联未知分开表达。
- 告警需要责任者、触发/恢复证据、确认与抑制、通知重试/失败记录和处置步骤；告警确认不解除回收责任。
- 首期提供受限 API/CLI 查询与观测出口，不以前置管理后台扩大范围；实际告警通道与接收配置必须在部署验证时明确。
- Audit/trace/指标中的敏感内容采用允许字段与限额控制，不能用原始工具参数、签名 URL、错误全文或模型正文充当默认长期记录。

规格、缺口矩阵和 V-AO-01 至 V-AO-12 验收项见 [审计与监控](audit-monitoring.md)。本轮完善的是设计，不代表审计、告警或故障恢复已实现。
