# AtomicAgent 审计与监控完整性审查及规格

2026-09-14 范围更新：A 管理台已随 v0＋A 拆分接受，见 [PRD 第 10 节](PRD-v0.md#10-已批准的-a-管理台范围)。下文“首期不新增／无需管理 UI”是原规格的历史范围；本目录的审计、健康和异常语义继续适用，现由真实管理台及 API 共同呈现，仍未完成产品验收。

更新：2026-09-13。结论：原需求包含进度事件、部分用量与清理状态，但审计和监控尚不足以形成可验收闭环。本文补齐设计；当前项目仍无运行代码，因此“已有”只表示原文档已定义，不能理解为功能已实现。

沿用：自有后端、外部只读、无人值守、任务终态清理、任务记录 7 天、产物 24 小时。首期不新增管理后台或任务 webhook。审计采用操作元数据，完整提示词、原始模型对话和思维过程不作为默认审计内容。

## 1. 原设计缺口和本轮补齐范围

| 编号 | 检查项 | 原文档状态/依据 | 本轮补充 |
| --- | --- | --- | --- |
| AO-01 | 主体与授权责任 | API 合约只有调用方访问约束 | actor/发起方、动作、对象、授权版本、结果与来源 |
| AO-02 | 执行依据可追溯 | 有版本化配置和输入摘要 | 固定执行清单、配置变更/停用、实际加载与使用分别记录 |
| AO-03 | 工具/模型执行证据 | SSE 可带工具名与用量 | 调用身份、父子与重试关联、拒绝/未知结果、覆盖程度 |
| AO-04 | 审计写入与故障语义 | 没有独立要求 | 关键操作可靠记账、异步导出、补记、停止/清理保底路径 |

| AO-10 | 观测系统自身健康 | 未定义 | 丢弃/积压、采集心跳、导出失败、审计记录缺口 |
| AO-11 | 保留期与清理冲突 | 记录 7 天，失败继续回收 | 过期访问阻断、物理删除核验、已确认的最小未完成资源责任例外 |
| AO-12 | 验收方法 | 验证计划无专门闭环 | 文末逐项故障、反例和查询证据 |

## 2. 四类信息分别服务什么目的

| 信息 | 回答的问题 | 可靠性与可见性 |
| --- | --- | --- |
| 任务审计记录 | 谁依据哪版授权/配置对什么对象做了什么，结果证据如何 | 不按采样省略关键操作；平台内受限查询；在保留期内追加纠正而非改写旧事实 |
| 任务进度事件 | 某个 Run 现在进行到哪里 | 授权投影，经 SSE 可重复投递；权威终态仍从 Run/Result 查询 |
| 监控指标与健康观测 | 平台是否正常、哪里积压、成本/资源是否异常 | 聚合计量和新鲜度；不靠指标证明某个具体操作确已发生 |
| 诊断日志与 trace | 某次故障在哪里、各阶段耗时多少 | 可限额、采样；不得作为唯一审计来源，不默认保留模型正文 |

技术映射可参考 OpenTelemetry 的 trace、metric、log 信号划分；这是观测技术的分类，不会自动提供本平台的责任审计或持久任务保证。[OpenTelemetry Signals](https://opentelemetry.io/docs/concepts/signals/)

首期语义要求是可查询、可导出、可核对，不以专门管理 UI 作为前置。观测技术的选型不反向决定领域对象。

## 3. 操作审计合约

### 3.1 最小记录结构

字段名是实施草案；允许关联对象暂时不存在，不能要求所有拒绝请求都已有 Run/Attempt。

| 字段组 | 内容与限制 |
| --- | --- |
| 身份 | `audit_id`、事件版本；可靠生产者身份和生产者事件身份用于去重 |
| 主体 | `actor_type/actor_id`、可选 `initiated_by`；鉴权失败使用 anonymous/unverified，不信任请求自报身份 |
| 操作对象 | `action`、`target_type/target_id`、`caller_scope`；Run/Attempt/invocation/resource/config 修订按需关联 |
| 原因与授权 | `decision`、受控 reason code、策略修订、执行清单身份、授权范围摘要 |
| 结果与证据 | 操作 requested/allowed/denied/observed_succeeded/observed_failed/unknown；证据类型与来源，不保存不可信 success 原文作结论 |
| 时间与因果 | 发生时间、平台记录时间、生产者序号；request/trace/causation 关联用于定位，不以墙上时钟排序代替状态版本 |
| 完整程度 | observed/partial/unknown、缺失原因；延迟补记说明观测时间与补记时间 |
| 受控摘要 | 配置/输入/产物身份和摘要、数量/大小；禁止密钥、签名下载 URL、完整工具参数/返回体和任意错误原文 |

一个操作可以有意图和结果两条相关记录；记录缺少结果时状态是未知，不能默认成功。供应商返回成功也只证明对应供应商操作，不证明平台的产物事务或回收已经完成。

记录来源、访问控制、敏感内容最小化和完整性保护参考 OWASP Logging 指南；下面的事件目录和失败策略是针对 AtomicAgent 的设计，不是外部规范强制的产品范围。[OWASP Logging](https://cheatsheetseries.owasp.org/cheatsheets/Logging_Cheat_Sheet.html)

### 3.2 首期必需事件目录

| 编号 | 范围 | 至少记录的动作和结果 |
| --- | --- | --- |
| A-01 | 接受与访问 | 提交接受/拒绝、幂等找回/冲突、鉴权/越权拒绝；对查询访问使用可控访问记录，不能靠原始 access log 代替授权事实 |
| A-02 | 配置 | 环境/Skill/MCP/model 修订登记、启用、停用；secret 引用绑定/轮换只记不透明身份和修订，不记值 |
| A-03 | 执行依据 | 执行清单固定、有效授权、资源创建意图/观测、配置加载成功/失败 |
| A-04 | 能力调用 | 可观察的工具/模型请求、授权结果、启动/返回/失败/未知、阶段重试；Skill 使用有要求时记录实际使用证据 |
| A-05 | 终止与验收 | 取消发起方、取消裁定、期限/预算触发、实际执行结束、输出检查、产物提交、Run 终态 |
| A-06 | 交付访问 | 结果读取、产物下载授权/拒绝、下载能力发放、可观察的传输结果；发出 URL 不等于对方下载完成 |
| A-07 | 回收和过期 | 回收责任登记、停止/删除/核验、重试/逾期、文件过期访问拒绝、物理删除核验 |
| A-08 | 运维处置 | 失联接管或 fencing、强制回收、异常确认/抑制/恢复、审计查询/导出和拒绝 |

平台维护者修改版本化清单同样要产生配置修订证据：由部署/登记动作导入，不能因为没有管理后台就没有配置审计。带 `secret_ref` 的有效清单属于内部材料，客户进度投影不暴露宿主路径、节点信息或 secret 名称。

MCP 的只读注解和 Agent 的工具事件都不足以证明所有出站动作受控。承诺完整审计的工具与模型调用必须经过不可绕过的受控接入边界；尚不能实现时，报告覆盖不足并拒绝把该配置标为满足完整审计要求。

### 3.3 权威事实、写入故障与退化

采用“平台内可靠记录，观测导出异步”的结构，不把外部日志平台的可用性变成每一步执行的同步依赖。Run 状态变化与对应关键审计事实/待导出记录具有同一持久化边界；投影消费者用稳定身份去重。此决策不要求事件溯源或指定消息队列。

| 故障位置 | 已确认行为 |
| --- | --- |
| 指标/trace 导出失败 | 有界缓冲、重试，记录丢弃数与积压；已接受任务不因纯遥测故障重跑或改终态 |
| 外部审计查询/导出服务失败，内部记录完好 | 继续执行，标记导出延迟，恢复后补投并去重 |
| 平台关键审计/任务存储无法写入 | 停止接受新 Run、新授权和新执行启动；不能返回已经可靠接受或已经成功提交 |
| 已运行任务丢失必要记录能力 | 保持有限停止路径，不再放行无法记录的新增能力；本地有界应急记录可用时持久缓冲，否则停止并将证据缺口标为未知 |
| 取消/强制终止/回收期间审计故障 | 停止和回收动作不能被故障永久阻断；保留尽可能可靠的意图和资源身份，恢复后核对补记，不伪造当时已记录 |
| 全控制面不可用 | 执行侧期限/资源到期提供独立终止保障；恢复后按 provider 资源身份对账，不凭任务表旧状态判定已清理 |

其中“审计不可写时拒绝新执行、保留停止/回收通路”已由用户在 2026-09-13 确认，见 [ADR 0006](adr/0006-audit-and-observation-boundaries.md)，尚不是已实测保证。

在保留期内，普通运行账号不能更新/删除审计事实；纠错新增关联记录，留存到期由专门责任执行。不能仅凭应用层 append-only 声称数据库管理员也不可篡改；需更强完整性证据时另行设计独立校验/归档，不在首期暗含该保证。

### 3.4 查询与权限

- 调用后端只读自己 Run 的状态、结果、授权进度；不得通过猜 ID 读取其他调用身份的数据。
- 内部审计读取、运行健康读取、强制处置是分别授权的能力；有 metrics 读取权不等于有结果正文读取权。
- 审计查询支持时间、actor、action、Run、目标、结果类型过滤及稳定游标分页；导出需限额和权限，首期可以使用 API/CLI。
- 查询/导出审计本身记一次访问记录；审计写入不递归产生“审计写入的审计”。
- 指标、trace、原始错误和审计接口不向公网匿名暴露。异常摘要使用 reason code 与有界字段，不拼接秘密或用户任意字符串。

## 4. 监控必须覆盖的对象和口径

### 4.1 指标目录

指标名称为建议。平台以持久事实去重计数或从权威状态计算 gauge；SSE 重播不能重复增加业务完成数。

| 编号 | 观测对象 | 最小指标/维度 | 数据来源 |
| --- | --- | --- | --- |
| M-01 | API 接受能力 | 请求量、接受/拒绝/冲突数、错误类别、请求延迟、存储可用性 | 鉴权/API 与持久接受结果 |
| M-02 | 排队与阶段推进 | queued/running 数、最老排队年龄、各阶段活跃数/耗时、超期限仍活跃数 | Run 状态、阶段时间与新鲜 worker 观测 |
| M-03 | 任务结果 | terminal 数按状态/原因分类、schema/产物验证失败、任务总耗时分布 | 权威终态/ValidationReport |
| M-04 | 执行存活 | worker 心跳年龄、lease 过期、控制权冲突、失联执行数、阶段最后推进时间 | 控制平面租约与执行观测 |
| M-05 | sandbox 容量 | 实际活跃数、CPU/内存/磁盘使用与限制、资源创建耗时/失败、清单和实际资源差异 | 资源 API/执行节点；含观测时间和 inventory 完整标志 |
| M-06 | 模型/MCP | 调用量、首个响应/完成耗时、429/鉴权/配置/服务错误、超时、重试数、初始化失败 | 受控调用边界/适配器；缺测单列 |
| M-07 | 用量预算 | token/调用数、已确认与估计成本分开、使用未知数、达到限额数、在途计量 | UsageEntry；按供应商/单位/来源归一化 |
| M-08 | 清理 | 未完成回收数、最老回收年龄、终态后仍活跃资源数、核验失败、超过 5 分钟目标数 | CleanupObligation + 资源实际观测 |
| M-09 | 产物与保留 | 上传/下载授权/传输失败、过期对象积压、实际删除延迟、容量、孤儿暂存数 | 对象存储和保留执行器 |
| M-10 | 审计与遥测 | 关键记录写入失败、导出积压/最老年龄、重复/缺口、脱敏拦截、buffer 丢弃、采集器心跳 | 审计管线与采集器自观测 |
| M-11 | 告警链路 | firing/acknowledged 数、处置年龄、通知尝试/失败、最近成功的端到端检测 | 异常与通知投递记录 |

按阶段观测流入、处理中、流出及最后处理时间，符合长任务处理系统的监控特征；不能只监控 HTTP 成功率。Prometheus 官方也建议对离线处理跟踪阶段进度，并警惕无界标签带来的开销。[Instrumentation](https://prometheus.io/docs/practices/instrumentation/)

`run_id`、`attempt_id`、文件名、URL、prompt、secret、任意错误文本不能作为常规时序标签。它们通过受限事件/trace 关联查询；指标维度采用受控枚举或有基数预算的 provider/model/phase/result。计量单位必须明确，不能将 Tokens、Credits 和币种金额混为一个 cost。

### 4.2 不会误导人的统计

1. **交付成功率**：统计窗口内已提交成功数 / 全部已提交终态数，同时展示取消、超时、失败分类与样本数。若另提供排除调用方取消的成功率，必须明示不同分母，不能替换原口径。
2. **总耗时**：Run 接受到终态提交，包含排队和产物提交；清理耗时单列。仅统计终态会漏掉卡住的任务，必须同时看在途年龄和期限违例。
3. **清理达标率**：已到清理目标时间的回收责任中，按时核验完成的比例；超过目标仍未完成者计未达标，不能只统计已经清理成功的样本。
4. **能力健康**：认证错误、配置错误、配额耗尽、服务端错误、网络超时分别统计；不把用户配置错误统一归咎 provider 宕机。
5. **用量完整率**：已覆盖计量范围 / 应覆盖范围，并单列未知范围；不以未收到 usage 当作 0 消耗。
6. **无数据**：空闲、采集失联、资源列表无权限和真实零资源必须分别表达。所有健康概览包含最近成功观测时间和覆盖范围。

### 4.3 日志和追踪边界

以平台 Run/Attempt 身份关联接收、排队、准备、执行、模型/工具、提交和回收。HTTP trace 结束后，任务执行可使用关联 trace/span 继续观测，不让 trace 生命周期决定任务生命周期。

首期低并发可尽量保留脱敏阶段追踪，但仍有大小/保留限额和显式丢弃计数。Agent 的自由文本输出默认不进入长期日志；shell/MCP 参数和错误可能含密钥，采用允许字段与受控摘要。trace 采样不允许省略必需的独立审计事实。

## 5. 告警与处置闭环

以下阈值是本轮实验建议，不是已确认生产 SLO。采用已有 60 分钟任务总期限、30 秒取消宽限、5 分钟清理目标；其他阈值登记为配置，不硬编码供应商能力。

| 编号 | 触发条件 | 默认处置责任与动作 | 恢复证据 |
| --- | --- | --- | --- |
| AL-01 | 关键任务/审计存储不可写 | 平台维护者；停止新任务/授权，优先保住取消与回收 | 新写入验证成功，积压/未知记录完成核对 |
| AL-02 | 任务超过自己的总期限仍有活跃执行 | 执行恢复器；撤销新增能力、停止并核查 | 实际执行终止，终态/回收责任一致 |
| AL-03 | 回收责任超过 5 分钟目标或发现孤儿资源 | 回收器＋维护者；按不变资源身份核验与重试 | 资源和临时授权确认已回收 |
| AL-04 | worker 租约失效、控制权冲突 | 维护者；fence 旧执行，先对账再接管 | 单一有效控制权，旧执行不再产生动作 |
| AL-05 | 最老排队超过配置阈值；实验可先设 5 分钟 | 维护者；核对容量、worker、供应商限额 | 队列年龄回到阈值内且观测新鲜 |
| AL-06 | 模型/MCP 鉴权失败或短窗持续服务错误 | 接入维护者；检查登记配置，禁止静默换 key/provider | 登记接入通过检查，错误条件消失 |
| AL-07 | 到期文件仍可访问，或物理删除持续逾期 | 存储维护者；先阻断过期读取，再完成删除 | 访问拒绝和对象删除各有证据 |
| AL-08 | 观测采集无心跳、审计导出积压、通知失败 | 平台维护者；使用独立探测发现观测链自身问题 | 新鲜采集、积压收敛、受控测试通知有回执 |

告警状态建议 `pending → firing → resolved`，确认接手、抑制期限和投递状态单独记录。抑制必须有操作者、原因和到期时间；不能关闭底层清理责任。恢复通知需要真实恢复证据，不能因 exporter 不再上报就恢复。

通知至少需要配置接收责任者、一个投递通道、去重、重试和失败可见性；首期无需新建管理 UI。投递服务接受不代表人已阅读，操作者确认不代表问题已解决。此处是功能设计，本次未向任何人发送消息，也未接通实际通知通道。

`/live` 表示进程存活，`/ready` 表示能够可靠接受任务；资源清理、对象存储、provider 与观测链健康分别展示。独立于被观测 worker 的资源到期和巡检路径不可省略，避免 worker 自己挂了同时失去唯一告警/清理来源。

## 6. 保留、删除与最小例外

| 数据 | v0 保留规则 |
| --- | --- |
| Run 对应审计、脱敏进度、结果清单 | 随 Run 终态后保留 7 天；执行中保留，不从提交时间提前过期 |
| 无 Run 的拒绝、配置修订操作、审计访问记录 | 记录时间起 7 天；运行中的执行清单仍保留所需固定依据 |
| 文件产物 | 终态后 24 小时；到期先禁止访问，再核验实际删除，两个事实分别记录 |
| 诊断日志/trace/监控历史 | 首期不超过 7 天，配置限额；延长需明确新的用途和保留规则 |
| 原始提示词、完整模型对话、工具正文 | 不默认长期保存；相关临时副本随任务清理 |
| 未结束的资源回收责任 | **已确认例外**：常规数据到期仍删除，只保留不透明资源身份、责任类型、必要 provider 定位和下一处置时间，直到确认回收；闭合后 7 天删除最小处置记录 |

未完成回收的最小记录不能携带 prompt、文件正文、结果 JSON、secret 值或完整会话，也不能成为无限延长其他数据保留的理由；其积压和年龄需要监控。该例外与审计故障策略已在 ADR 0006 记录为 accepted。

输入摘要只用于完整性/归属核对，不因为“是 hash”就对外公开所有敏感材料指纹。查询到期对象时不重新启动原任务；授权链接过期与文件已删除分别处理。
