# 将关键操作审计与观测投影分离，保留独立回收责任

原设计把脱敏事件、用量和清理状态作为观测入口，但没有定义审计写入失败或常规记录过期时的责任边界。由平台可靠保存关键操作及执行依据，SSE、指标、trace 和外部审计查询作为投影或导出；外部遥测故障不改变任务结果。

取舍一：平台关键记录不可写时停止新任务、新授权和新执行，取消/停止/回收仍有受限保底通路，恢复后核对补记。代价是记录能力会影响接纳可用性，但避免无法追溯地继续扩大任务执行。

取舍二：常规任务与审计数据仍按 7 天保留；仅对未完成回收保留最小资源定位和责任记录直到核验完成，不保留业务正文，闭合后 7 天删除该最小记录。代价是增加一类独立保留责任，收益是常规数据过期后不会遗失孤儿资源。

2026-09-13 用户明确回复“新增策略确认使用建议”，两项取舍均已接受，并纳入 v0 PRD；这不表示功能已经实现或通过实验。实现和故障验收见 [审计与监控规格](../audit-monitoring.md)。
