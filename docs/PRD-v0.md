# AtomicAgent v0 PRD

版本：v0＋A · 更新：2026-09-14（原 v0 基线：2026-09-13）

需求状态：基于已确认共同理解及已接受 ADR 0001–0006 综合。2026-09-14 用户接受 v0＋原型 A 的 33 张 tracer-bullet 拆分、逐票验收边界及本地 Markdown tracker；管理台范围见下文第 10 节。本文定义首期完整交付范围，不表示实现、模型兼容性或生产验收已完成。

## Problem Statement

自有后端需要把一项业务工作交给 AI 完成。普通 LLM API 返回文本或工具调用意图，后端仍需自行实现工具循环、文件装载、代码执行、环境准备、输出验证、失败恢复和资源回收。每接入一种新任务，重复建设这些能力会增加开发和运行负担。

Claude Code／Claude Agent SDK 已能在工作环境中执行多步任务，但直接包装一次 CLI 或 SDK 调用，不能解决后端调用所需的持久任务身份、断连续行、幂等、结果交付、权限边界和清理责任。Agent 自述完成、进程退出、文件可下载和资源已删除，也不是同一件事。

平台还需要回答：谁按哪版配置发起任务、实际加载和使用了哪些能力、哪里失败、消耗是否完整、任务结束后是否仍占资源，以及审计或监控自身故障时如何处理。缺少这些能力，调用后端无法可靠使用和维护这类任务。

## Solution

AtomicAgent 为自有后端提供独立 Agent 任务 API。调用后端提交提示词、输入文件引用、已登记的环境／Skills／MCP／模型配置和输出要求，平台在独立 sandbox 中运行固定的 Claude 引擎，完成多轮推理、工具调用和文件处理，再交付经过校验的 Result 与 Artifact。

一次 API 提交对应一个持久 Run，不要求同一条 HTTP 连接一直保持。短任务可以在有限等待内取回结果；长任务或断连后通过 Run 查询和 SSE 继续观察。显式取消才请求停止，任务到达终态后清理执行空间，产物转存后保留 24 小时，任务记录保留 7 天。

v0 同时支持两条完整业务路径：

- **文件处理**：上传 CSV／JSON → 按规则在 sandbox 中运行代码 → 验收统计结果和输出文件 → 转存 → 清理 → 下载。
- **资料研究**：提交问题和允许的数据源／只读 MCP → 获取并分析材料 → 交付 Markdown 报告、结构化结论与来源 → 清理 → 取回结果。

任务可以在自身执行空间写文件，外部业务系统只读。平台使用 OpenSandbox 管理执行空间，以薄适配层直接接入 Claude Agent SDK；平台自己承担任务状态、授权、交付、审计和回收责任。

v0 的完成标准是：两类任务均通过真实引擎与获准模型连接完成全链路，并取得幂等、取消、失联、权限、过期、审计退化和资源回收的验证证据。只生成报告文本、只通过替身测试或只运行一个容器均不足以完成 v0。

## Implementation Decisions

以下是已确认的产品和架构约束；未指定的语言、数据库、队列和监控部署方式由实施设计决定，不以新增组件数量作为完成指标。

### 1. 领域及职责

采用单一 AtomicAgent 领域，划分任务执行、输出交付、资源回收、运行保障四组职责，不要求拆微服务。对外仍是一个任务平台。

| 对象组 | 责任与约束 |
| --- | --- |
| Run、Attempt | Run 是接受后的逻辑任务；一个 Run 在 v0 最多一次实际 Agent 执行，未启动可以没有 Attempt；重新观察或接管同一执行不创建 Attempt |
| InputObject、InputBinding | 分离输入源材料与任务装载副本，固定内容身份、权限和任务内位置 |
| ConfigurationRevision、ExecutionManifest、CapabilityGrant | 固定配置修订、实际执行依据及授权；配置名称或提示词不能代替有效权限 |
| SandboxAllocation、CleanupObligation | 持有实际资源归属与独立回收责任；任务终态不证明资源消失 |
| InvocationRecord、UsageEntry | 描述可观察调用与有来源的用量，保留未知与重试关系 |
| ValidationReport、Result、Artifact | 分别拥有输出验收依据、提交结果与独立文件交付生命周期 |
| AuditRecord、RunEvent | 分离可信操作责任与调用方进度投影，进度不能裁定终态 |
| HealthObservation、OperationalIncident | 表达带新鲜度的健康事实以及需处置的异常，确认不等于恢复 |

任务接纳与幂等、输入配置解析、Claude 执行适配、结果验收与转存、资源对账回收、审计与观测为必需模块职责；实现可以合并部署。它们必须使用一致的任务身份和受控状态变更。

### 2. 固定引擎和配置入口

- 固定 Claude Code／Claude Agent SDK，使用 OpenSandbox；首期不叠加 Sandcastle。
- 先在独立 Linux 节点验证 Docker 路径，再以相同工作负载评估 gVisor；Docker 功能通过不等于强隔离通过。
- 每次任务固定 runtime、SDK／CLI、镜像、模型身份、配置修订、输入摘要、输出契约与有效限制。执行清单固定后才能开始 Agent。
- Claude 的配置来源必须受控，隔离配置目录和会话材料，避免从宿主或前次任务隐式继承设置。
- 环境、Skill、MCP、模型配置均先登记并版本化，请求只能选择和组合允许的能力、参数与限额；不开放任意宿主挂载、权限或启动脚本。
- 必需 Skill／MCP 加载失败必须明确失败；“文件已复制”不能替代加载与可调用证据。要求实际使用时，还需独立调用证据。
- 模型连接与 Claude runtime 分开登记。用户最初指定的 Qwen Token Plan 仍需核对用途限制和兼容性；没有默认切换套餐、endpoint 或模型。真实接入固定确切 profile 后才能验收。

### 3. 输入和外部权限

上传材料完成校验后才可引用。请求引用调用方有权访问、未过期且内容完整的文件或前次产物，路径必须限制在任务工作区内。失效、越权、重复目标或不安全路径应在可判断的最早阶段明确拒绝或准备失败，不能覆盖任意任务文件。

新任务显式引用前次产物时形成自身输入副本；原产物按原期限过期，新副本由新任务清理。任务结束不能删除其他任务仍合法使用的共享源材料。

Agent 只可修改本任务执行空间，外部业务系统只读。工具权限、受限凭据、网络出口与文件边界共同执行此限制；MCP 注解、提示词或单一 SDK 预批准列表不构成完整授权边界。受控运行身份和平台验证器拥有权威，输入文件、网页、工具返回和 Agent 文本不具有提权能力。

配置停用默认阻止新任务使用，不修改已有执行清单；需要停止运行中能力时执行显式撤销和终止，并核验实际生效。

### 4. 任务 API 与协议

对外提供上传输入、提交任务、查询 Run、观察 SSE、显式取消、读取 Result、查询／下载 Artifact 七类能力。接口路径和字段拼写遵循后续 API 实施规格；稳定承诺是本节的业务语义，不直接暴露 Claude 原生输出作为公共协议。

| 合约 | v0 要求 |
| --- | --- |
| 请求 | 提示词、输入引用及相对位置、登记环境／模型／Skills／MCP、受约束参数、输出 schema 和必需产物、允许覆盖的任务限制 |
| 接纳 | 先可靠保存 Run 与幂等绑定，再返回接受；鉴权或验证失败不伪造已接受 Run |
| 幂等 | 调用身份内同 key、同内容得到原 Run；同 key、不同内容冲突；并发提交不重复执行；内容比较包含影响执行的输入和配置 |
| 有限等待 | 至多 30 秒，未终结返回任务身份；HTTP 超时或断连不取消，原 key 可找回响应丢失的提交 |
| 查询 | 返回权威状态、当前阶段、终止原因、已提交结果／产物引用、用量及独立清理状态 |
| SSE | 稳定事件身份／顺序与恢复游标；可能重放，客户端可去重；游标过期明确反馈并支持改查 Run；EOF 不等于成功 |
| 取消 | 记录意图与裁定；请求已接受不等于实际执行已停止；终态由原子裁定确定 |
| 结果访问 | 按调用身份授权；结果提交前不能返回成功 Result，过期不触发重跑 |
| 产物访问 | 下载授权、链接有效期、文件保留期和实际传输分别记录；签发链接不等于已下载 |

建议公开状态为 queued、running、succeeded、failed、cancelled、timed_out，执行阶段单列。排队或准备中也可因取消、期限或失败到终态；任何路径都必须满足一个 Run 只有一个已提交终态。旧 worker、迟到事件和迟到取消不能覆盖已提交状态。

内部运维提供受限审计查询／导出、分项健康、聚合指标、异常查询与资源回收单查询；受控命令支持配置登记／停用、授权撤销、异常确认／限时抑制及回收处置。维护命令具有独立权限与审计身份，不开放任意宿主 shell。

### 5. 完成、失败与竞争

只有以下条件全部满足，Run 才提交 succeeded：结构化结果符合声明 schema、必需 Artifact 已验收并转存、ValidationReport 与 Result／产物清单已可靠提交。成功提交时必须已登记相关资源的清理责任。

Agent 正常退出、提供自由文本、声称工具成功或仅输出正确数字均不能替代平台验证。文件样例使用明确数据断言；研究报告分别检验格式、来源取得与结论对应，不能承诺机械校验覆盖全部开放研究事实。

失败分类至少区分输入／配置、必需能力、资源准备、运行接入、执行失联、输出不合格、产物提交、期限／资源预算、缺输入／授权和显式取消。返回受控原因和有界诊断摘要，不能用半成品冒充成功 Result。

取消与结果提交使用同一权威裁定边界；已提交成功不被迟到取消覆盖。实际资源尚未核验停止或删除时，保留清理未完成／未知事实，即使业务已经到终态。

### 6. 恢复和限制

- 允许环境准备、短暂模型错误、上传或结果提交等明确阶段有界重试；每阶段最多追加 2 次，始终计入 Run 总期限与累计预算。
- 将 SDK、平台与调用适配器重试纳入同一观测和限制，不因嵌套重试静默放大请求次数。
- Agent 已执行后不自动重跑整个任务；默认关闭 Agent 输出格式修复。业务重做由调用后端创建新 Run。
- sandbox 创建或 Agent 启动响应未知时，先按稳定操作／资源／执行身份对账，不能假定没执行而再启动。
- worker 失联先核验已有执行和控制权；旧控制者必须失去继续控制和提交结果的能力，才能安全接管同一执行。无法安全接管时终止原执行并明确失败，不启动第二个 Agent。
- 产物上传或结果提交失败只恢复相关阶段。已经转存但尚未提交的对象必须有归属和回收责任。
- 相同幂等 key 在记录保留期内仍找回失败或产物过期的旧 Run；记录过期后不承诺原幂等保证继续有效。

| 实验配置 | 已接受值／语义 |
| --- | --- |
| 并发运行任务 | 2 |
| 默认任务总期限 | 60 分钟，可按登记配置调整；含排队、准备、执行、收集、验证与提交 |
| HTTP 提交等待 | 最多 30 秒 |
| 显式取消宽限 | 30 秒，随后执行层强制终止；实际停止与清理另行核验 |
| 终态清理 | 立即触发，5 分钟内核验完成为待实测目标；失败继续回收 |
| 输入总量／产物总量 | 50 MiB／100 MiB |
| 单 sandbox | 2 vCPU、4 GiB RAM |
| 阶段重试 | 最多追加 2 次，不重置累计期限与预算 |
| 模型预算 | 以固定 profile 实际能计量和强制的维度定义；未知计量显式呈现，不承诺未验证的硬金额上限 |

这些是可调实验起点，不是生产 SLA 或实测容量。资源限制必须由选定执行层真正强制。控制面完全故障时，独立于失联 worker 的执行期限、资源到期和巡检路径仍需限制占用。

### 7. 回收与保留

每份 SandboxAllocation 与临时对象都有归属；所有终态和准备失败都触发 CleanupObligation。清理覆盖任务进程、工作目录、临时配置／会话、任务有效凭据能力及归任务所有的暂存。

回收遵循待执行、执行、核验、完成的过程，失败可重试。超时、权限不足、列表不完整或删除请求发出，均不等于已回收；完成需目标身份、完整且新鲜的权威观测、时间和结果。

| 数据 | 保留和删除要求 |
| --- | --- |
| 已交付 Artifact 文件 | Run 终态提交后 24 小时；到期不可再访问，物理删除另行核验 |
| Run 状态、Result JSON、清单、脱敏事件、幂等记录、对应审计 | 终态提交后 7 天；执行中的必要记录不提前过期 |
| 无 Run 的拒绝、配置操作和审计访问记录 | 记录后 7 天；活跃 Run 仍持有所需固定执行依据 |
| 未使用上传 | 暂存 24 小时；失败上传与未提交产物残留同样进入回收管理 |
| 输入工作副本、原始对话、运行临时材料 | 随任务执行空间清理，不默认长期保存完整正文 |
| 脱敏诊断、trace、监控历史 | 首期不超过 7 天，受容量限额控制 |
| 未完成回收的最小处置记录 | 常规数据仍按期删除；只留不透明资源身份、必要 provider 定位、责任类型和下一处置时间，直到核验回收，随后 7 天删除 |

最后一项是已确认的最小例外，不保留 prompt、输入正文、Result JSON、secret 值或原始会话，不延长产物可访问期。例外积压和年龄需持续监控。

### 8. 审计与退化

AuditRecord 记录可靠身份、动作、对象、授权／配置版本、决策、观测结果、时间与因果关系、证据来源和覆盖程度。拒绝请求可没有 Run／Attempt，不信任其自报身份。未知结果和补记说明原观测与记录时间，不能伪造完整性。

必需审计覆盖八组操作：接纳与访问、配置变更、执行依据及资源创建、可观察能力调用、取消及结果验收提交、结果／产物访问、回收与过期、运维处置及审计读取／导出。

关键状态与必要审计事实／待导出记录位于同一可靠持久化边界，外部导出异步、可去重；不强制事件溯源。正常运行账号只能追加事实，纠正采用关联新记录；到期删除由独立留存责任执行。不承诺数据库管理员不可篡改。

| 故障 | 已确认处置 |
| --- | --- |
| 仅外部指标／trace 或审计导出失败 | 有界缓冲、重试、可见积压与丢弃；内部事实完好时继续任务，不重跑或改终态 |
| 核心任务／必要审计记录不可写 | 停止接纳新 Run、发放新授权和启动新执行；不能返回虚假的可靠接纳或成功提交 |
| 已运行任务无法记录必要新调用 | 不再放行无法记录的新增能力；可用时采用有界持久应急记录，否则停止，证据缺口记未知 |
| 停止／回收遇到记录故障 | 保留有限保底处置路径，尽可能可靠保存身份与意图，恢复后对账补记；不因审计故障永久阻断清理 |

可观察调用不等于全进程行为回放。若配置声称完整工具／出站审计，必须通过不可绕过的受控边界验证；否则标记 partial／unknown 并拒绝将其认定为满足完整覆盖。

### 9. 监控、异常和权限

监控覆盖 API 接纳、排队与阶段推进、终态与验收、worker 控制权、实际 sandbox 资源、模型／MCP、用量与限制、回收积压、产物到期、审计采集以及通知链。健康输出包含来源、时间和覆盖范围；存活、可接纳、组件健康和未知分别展示。

成功率展示样本数及成功／失败／取消／超时分类；总耗时从接纳到终态提交，清理耗时单列，同时展示未结束任务年龄。清理达标率包含超过目标仍未完成的责任。用量区分来源、单位、增量／累计、估算／确认和覆盖程度，SDK 估算与供应商账单不得重复相加，未知不能填零。

Run／Attempt／文件名／URL／任意错误等无界值不作常规指标标签，使用受限事件或 trace 关联。SSE 重放不重复增加任务计数，trace 采样不省略关键审计。

必须能检测并处置：核心记录故障、任务过期限仍活跃、回收超过 5 分钟目标或孤儿资源、worker 失联／控制权冲突、队列持续积压、模型／MCP 接入错误、到期文件仍可访问或删除逾期、观测／通知链故障。队列年龄可先以 5 分钟作为可调实验阈值，其他窗口依部署配置和测量确定。

OperationalIncident 具有责任者、触发及恢复证据、处置动作、接手确认、有限抑制和通知状态。确认不是恢复，抑制有操作者、原因和到期时间；采集失联不能自动消警。通知通道具备去重、重试和失败记录，通道接受不等于人已阅读。部署时配置至少一个通道与接收责任者，并取得受控投递证据。

调用方业务读取、审计读取、健康读取和强制处置分别授权。默认观测不保存密钥、签名 URL、原始参数／正文、完整错误或原始模型会话；采用字段允许清单、长度／容量限制和受控摘要。审计读取／导出本身留痕一次，不递归记录日志写入行为。

## Testing Decisions

### 测试入口和证据边界

以**对外任务 API 的可观察行为**作为主要验收入口。通过提交、查询、SSE、取消、结果和产物访问驱动完整流程；用受限审计／健康／回收查询和实际 provider 资源观测核实副作用。A 的管理行为增加真实浏览器入口，并验证服务端权限及刷新持久性；这些边界已随 2026-09-14 拆分接受。

当前只有设计文档，没有代码、现成测试框架或可复用测试模块。已有验证计划中的两类样例、平台故障矩阵和 V-AO-01–12 是验收先例，不是已通过测试。

新故障注入边界优先置于外部依赖适配处：sandbox 生命周期、模型／MCP、持久存储／对象存储、时间和遥测投递。尽量复用同一 API 验收流程，通过受控故障配置验证边界；不为每个内部函数新造一套测试接口。少量针对幂等裁定、时间、用量归一化的确定性测试只检验领域行为，不镜像实现。

证据分开记录：

- **确定性合约与故障实验**：替身、受控时间、并发与故障注入用于复现状态、重试和保留行为。
- **真实集成**：固定 OpenSandbox、Claude SDK／CLI 和获准模型 profile，完成两类任务，记录实际资源和调用证据。
- **部署边界**：真实资源限制、网络／文件／权限隔离、取消和回收，以及观测通知链；Docker 与 gVisor 分别报告。
- **业务内容核验**：独立算出文件统计；核对研究结论与本次来源，格式通过不代替语义正确。

### 发布验收门槛

v0＋A 需完成 AC-01–28 及 A-AC-01–12 的全部适用行为，没有适用项可以仅以“文档完成”关闭。真实模型、部署隔离、计量覆盖和通知通道必须分别报告通过／失败／未验证；固定材料不能替代真实网络研究，Docker 不能替代 gVisor 验证。gVisor 评估结果可以是“不适用／不通过”，但必须明确部署实际采用的隔离边界，不能据此宣称强隔离已通过。

若尚无获准模型 profile，允许完成确定性实现与故障实验，但真实两类任务验收保持未完成。若某种金额硬限制无法实施，应拒绝宣称或接受该不受支持的约束，明确实际可强制的限制维度。

## Out of Scope

- 面向公开租户的 SaaS、租户计费、商业套餐和收费系统。
- 外部业务写操作，包括自动发邮件、修改第三方记录、提交代码或发布内容。
- 持久聊天会话、跨 Run 隐式续接、共享工作区、人工授权／输入等待工作流。
- 多 coding agent 引擎切换、平台级多 Agent 编排、自动重跑整个已执行任务。
- 任意宿主挂载、任意启动脚本、请求自授权限、任意未登记 MCP／Skills。
- 任务完成 webhook、OpenAI Chat Completions 兼容层；管理台超出第 10 节的探索能力。
- 首期叠加 Sandcastle、前置 Kubernetes／Temporal，或围绕 Git 分支／worktree／合并建立业务模型。
- 无限期文件、原始对话和完整思维过程留存；隐式延长业务数据保留期。
- 未验证的生产 SLA、真实账单精确性、硬金额上限、全进程审计覆盖或管理员不可篡改保证。
- 自动购买套餐、切换用户模型账户、部署到未指定基础设施或在本次文档任务中调用计费服务。
