# v0 逐票实施推进记录

启动日期：2026-09-14。依据：[已批准票务计划](ticket-plan.md)。用户授权以 goal 持续推进，每张票使用全新上下文的 subagent 执行 `$implement`。

## 执行约定

- 每票 agent 使用 `fork_turns=none`，仅接收票路径、技能入口、工作区和必要授权边界；自行读取当前仓库事实。工具无法发送 `/clear`，因此记录为新上下文，不伪称执行命令。
- 同时仅有一名实施 agent 修改产品代码。每票可启动两个独立 reviewer 做 Standards／Spec 审查；审查基线为本票启动 HEAD，修复与验证后独立提交当前分支。
- 优先按编号拓扑推进。上游已实现的接口可供下游实现与确定性验证使用；上游未完成的真实验收继续作为下游最终验收阻塞，不把代码依赖可用等同整票关闭。
- 完整需求保持不变。每票保留输入、行为、权限、持久化、失败／重复请求、审计、健康来源和适用 UI；真实模型、网络、业务内容、Docker／gVisor、通知、浏览器及人工证据分别列账。
- 不读取或打印无关凭据，不自行替换账户／套餐，不把模型或外部依赖替身结果作为真实验收。授权输入到达后再执行相应真实操作。
