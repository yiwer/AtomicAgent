## 已批准范围与原型取舍

用户本轮明确要求“v0 PRD 以及原型 A”拆票，并回复“接受”。本次交付范围为 v0＋A：既有 API 行为配上相应真实管理路径；PRD 第 10 节现记录正式范围及 A-AC-01–12，并移除原排除项中的管理后台。此前 API-only 范围保留为历史语境。

A 固定分组侧栏、真实工作区／身份入口、首页指标→异常→任务表、右侧依赖健康／最近获授权操作、任务及配置详情面板、发布前变更摘要和影响范围贯穿各票。01 只建承载首条行为的最小页面；对应功能完成时再开放导航与动作，不交付一套空页面。

已批准纳入的新增能力为：26 队列人工调序／暂停，27 Skills 来源候选审查，28 固定能力组合，29 角色权限编辑，30 三类任务功能开关，31 每日 token 预警。其最小语义已随整份拆分接受，并写入 PRD 及对应独立票；未经列出的原型行为不自动进入范围。

不纳入产品：B／C 切换、内存演示数据、随意切换模拟身份、手动标记任务成功／资源已删除、故障注入和“模拟调度下一项”。Agent 输出修复保持基线默认关闭，不实现原型探索开关；cron、周期任务、外部业务写、任务 webhook 和整项 Agent 自动重跑仍不在范围。故障注入只属于隔离的验收设施。

## 每张票必须遵守的交付规则

1. 每票打通一个用户可观察行为：API 或 A 入口→领域裁定→可靠持久化→适用的实际执行／存储／资源边界→返回与页面→行为验证。读取型运维票打通真实观测／查询，不强行新启动 Agent。
2. 每票带自己的正常、失败、重试／重复请求边界、权限、审计及证据。首票就有关键原子事实、最小鉴权与回收；后续故障票扩展具体恢复行为，不能先允许违反领域不变量再等后票修。
3. 每票限定一个窄场景和必要变化，控制在一个 fresh context；32 是可运行部署交付，33 是已实现系统的发布验收门槛，不能作为前序所有测试／安全工作的兜底。
4. 初始只支持受控实验路径。所需的能力未落地时明确拒绝；未知资源／消费／观测保持未知，不能填零或宣告成功。
5. 一张票完成时提供可运行命令、最短 API／管理台演示步骤、输入／动作／观察／证据出处，以及通过／失败／未验证结论。涉及真实执行的票需真实证据，替身通过不能关闭其真实验收。
6. 实现票引入的每种新动作同时记录 A-01–08 所属审计；每种依赖同时输出带新鲜度的健康数据、受控指标与适用异常来源。20／23／24 提供查询与展示闭环，不替其他票补所有采集。
7. 20／23／24 可使用当时已存在的真实对象独立演示，尚未实现的来源明确标“未接入”。两票先后可互换：来源先落地则保存事实待视图接入；视图先落地则后续功能票负责注册来源并验收。33 检查完整覆盖。
8. 所有管理请求由真实身份授权；刷新持久、直接 API 拒绝越权、错误可恢复、观测无敏感正文是每个 A 功能的验收内容，不能以禁用按钮代替。
9. 全部证据分别归档：确定性合约／故障、真实引擎与模型、真实网络、业务内容核验、Docker、gVisor、通知投递、浏览器及人工验收。

## 外部条件与开工边界

- **01 的真实验收**需要获准模型 profile、确切 endpoint／model、服务端凭据绑定及指定 Linux 实验节点。它们尚无可核对配置；实现可先推进确定性路径，但本票真实执行不能用替身关闭，也不能默认换 Qwen 套餐／账户。
- **07／27**分别需获准只读 MCP／来源与登记 Skills 仓库；示例地址不作为可用依赖。
- **25**需指定责任者、部署通道和试发授权；可先完成受控接收端，实际通知证据独立待完成。
- **32**需指定部署节点及可评估的隔离运行方式。
- 这些是实施输入，不要求本次拆票提前交出密钥，不授权当前读取凭据、计费调用、部署或发消息；未具备时保留具体阻塞事实。
- 基础故障路径安全失败即可先完成窄场景；若底层不支持稳定启动身份、停止或回收核验，应在最早切片暴露限制，不发布“已验证可用”结论。

## 编号概览

编号按依赖拓扑排列；Blocked by 只列直接阻塞，已移除可由其他依赖推导的冗余边。编号连续不代表必须串行实现。

1. **01 — 提交提示词并在 A 中取回已校验 JSON** · Blocked by：无 · PRD + A。调用方提交仅需结构化 JSON 的小任务；平台固定一个登记环境／模型修订，经 OpenSandbox、Claude 执行、平台校验、持久提交及终态回收，维护者在 A 的任务表与详情查看结果。

2. **02 — 上传文件并交付可下载的处理结果** · Blocked by：01 · PRD + A。上传 CSV／JSON，绑定任务内输入位置，实际执行代码生成统计和必需文件；在 A 的任务详情读取 Result 并在 sandbox 清理后下载 Artifact。

3. **03 — 提交响应丢失后找回同一 Run** · Blocked by：01 · PRD + A。调用后端并发重传或丢失接受响应后，以原幂等键找回原 Run；A 中始终只出现一个逻辑任务。

4. **04 — 有限等待与 SSE 断线续看** · Blocked by：01 · PRD + A。短任务可在有限等待内返回结果，长任务返回身份；A 的详情通过可恢复 SSE 展示进度，断连后继续观察同一 Run。

5. **05 — 发布环境与模型修订并用于新任务** · Blocked by：01 · PRD + A。维护者从 A 配置面板登记环境／模型、预览变更及影响、发布固定修订，调用方选择修订执行任务；停用阻止新选择。

6. **06 — 登记 Skill 并证明任务实际使用** · Blocked by：02、05 · PRD + A。维护者登记一个固定 Skill，调用方选择它完成文件任务，A 展示所请求、装载、可调用及实际使用的不同证据。

7. **07 — 通过登记只读 MCP 交付研究报告** · Blocked by：02、05 · PRD + A。维护者登记 MCP 并检查连接及只读能力；调用方提交比较问题，获取当次材料，交付带来源的 Markdown 与结构化研究结论。

8. **08 — 以前次产物显式创建新任务** · Blocked by：02 · PRD + A。调用方显式选择仍有效的前次 Artifact 作为新 Run 输入，在详情核对输入来源和独立副本，完成新的文件任务。

9. **09 — 取消任务并核验实际停止** · Blocked by：01 · PRD + A。调用方或获授权维护者从 API／A 请求取消，持续看到取消裁定、实际停止及独立清理结果。

10. **10 — 让恶意任务在隔离与只读边界内失败** · Blocked by：07 · PRD + A。文件或研究输入试图越界时，平台实际阻断并返回受控失败，A 展示可核对原因；后续任务仍获得干净执行空间。

11. **11 — 修改限额并实际限制后续任务** · Blocked by：02、05、09 · PRD + A。维护者在 A 审阅并发布执行限额，新 Run 按固定限制排队及运行；超期或超限被实际限制／终止并可查原因。

12. **12 — 在任务与额度页查看可信用量** · Blocked by：01 · PRD + A。调用后端和维护者查看 Run 消耗及聚合用量，知道来源、单位、估计／确认及未知范围，并可供实际支持的预算维度使用。

13. **13 — 短暂故障只重试当前阶段且受累计预算限制** · Blocked by：11、12 · PRD + A。暂时性准备或模型故障在同一 Run 的既定阶段有界恢复；调用方看见次数、消耗和耗尽原因，不发生整项 Agent 重跑。

14. **14 — 创建或启动回执丢失时找回既有执行** · Blocked by：01 · PRD + A。sandbox 创建或 Agent 启动响应丢失后，平台用稳定身份对账，A 呈现实际资源与执行观测，避免重复执行及无主资源。

15. **15 — worker 失联后安全接管同一执行或停止失败** · Blocked by：09、14 · PRD + A。worker 失联时维护者看到控制权及既有执行的核验结果；平台安全接管观察同一执行，不能接管则停止并明确失败。

16. **16 — 上传或提交中断后恢复交付而不重跑** · Blocked by：13 · PRD + A。Agent 已生成合格输出后，存储／提交故障只恢复文件转存或结果提交，调用方最终取回一次可靠交付或明确交付失败。

17. **17 — 从回收单重试处置并核验资源消失** · Blocked by：09、14 · PRD + A。维护者从 A 的 sandbox／回收详情按不可变资源身份请求重试回收，看到删除请求、核验中、失败／未知及真正完成。

18. **18 — 文件到期失效并保留最小未完成回收责任** · Blocked by：08、16、17 · PRD + A。文件到期后不能再下载，记录窗口内仍能查看 JSON／清单；常规数据删除后维护者仍可定位孤儿资源，完成处置后再删除最小记录。

19. **19 — 显式撤销运行中授权并核验停止** · Blocked by：06、07、09 · PRD + A。维护者从配置影响面板选择需要撤销的运行中授权，审阅影响后提交受控撤销，查看真正停止及回收进展。

20. **20 — 按独立审计权限查询和导出操作责任** · Blocked by：01 · PRD + A。审计读取者在 A 按时间、Run、主体、动作和目标筛选、分页及限额导出可信操作记录，健康读取者无法读取审计或业务正文。

21. **21 — 核心记录故障时停止新工作但仍可停止与回收** · Blocked by：17、20 · PRD + A。关键存储不可写时，A 明示退化并阻止新接纳、授权和执行；维护者仍能使用受限保底路径停止及回收既有资源。

22. **22 — 外部遥测故障时继续任务并展示有界退化** · Blocked by：20 · PRD + A。外部审计导出、指标或 trace 不可用时，任务按内部事实继续，A 显示观测延迟、积压及丢弃，恢复后去重补投。

23. **23 — 在 A 首页定位真实积压和未知健康** · Blocked by：01 · PRD + A。维护者进入 A 运维总览，按运行与回收指标→待处置异常→任务表查看当前事实，右侧查看依赖健康与最近获授权操作。

24. **24 — 处置异常并依据新鲜证据恢复** · Blocked by：17、23 · PRD + A。回收逾期等异常进入 A 待处置列表，维护者接手、限时抑制和执行处置，只有新鲜恢复证据才解除异常。

25. **25 — 通知异常并独立发现观测链失联** · Blocked by：24 · PRD + A。维护者为异常配置责任者与一个通知通道，A 显示通知去重、重试、失败及通道回执；独立探测能发现采集器和通知链自身中断。

26. **26 — 暂停调度或调整队首先影响待执行任务** · Blocked by：11 · A 新增。维护者在 A 查看等待队列、暂停／恢复新调度或将某个排队 Run 提到队首，实际调度在有效槽位内执行。

27. **27 — 从登记 Skills 仓库发现候选并审阅发布** · Blocked by：06 · A 新增。维护者登记允许的初始 Skills 来源，发现固定候选修订，经审阅发布后由新 Run 选择并使用。

28. **28 — 保存固定能力组合并用于提交任务** · Blocked by：06、07 · A 新增。维护者把登记环境、模型、Skills 和可选 MCP 固定为可复用组合，调用方或 A 提交入口选择组合完成普通 Run。

29. **29 — 调整角色权限并由服务端立即执行** · Blocked by：20 · A 新增。获授权的权限维护者审阅并修改管理角色能力，新请求按已生效策略获得允许或拒绝，A 与 API 表现一致。

30. **30 — 功能策略控制后续文件、研究和产物复用** · Blocked by：07、08 · A 新增。维护者在 A 审阅并更改文件处理、资料研究和前次产物引用开关，新请求由平台实际接纳或拒绝。

31. **31 — 达到每日 token 预警阈值后生成可处置异常** · Blocked by：12、24 · A 新增。维护者设置每日 token 预警阈值，A 依据可信用量展示已知消耗／未知项并产生一次可处置异常。

32. **32 — 在选定 Linux 部署边界复验两类工作负载** · Blocked by：10、11、15、21 · PRD 部署交付。维护者在固定 Linux 节点运行两类真实任务，比较 Docker 与 gVisor 的行为及隔离结果，取得可复现的执行和回收部署方案。

33. **33 — 交付可复现的 v0＋A 完整验收包** · Blocked by：03、04、18、19、22、25、26、27、28、29、30、31、32 · PRD + A 发布验收。维护者按可运行启动／验收说明走通两类业务、A 管理路径和全部已确认故障场景，取得真实容量与证据完整性报告。
