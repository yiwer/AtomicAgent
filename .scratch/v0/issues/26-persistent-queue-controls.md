# 26 — 暂停调度或调整队首先影响待执行任务

**What to build:** 维护者在 A 查看等待队列、暂停／恢复新调度或将某个排队 Run 提到队首，实际调度在有效槽位内执行。

**Blocked by:** 11 — 修改限额并实际限制后续任务

**Status:** ready-for-agent

**范围来源：** A 新增；2026-09-14 用户接受 v0＋A 拆分后发布。

**验收对应：** 原型 A 的已批准管理行为；完整页面及来源责任见票务计划。

**管理台验收对应：** A-AC-07。

## Acceptance criteria

- [ ] 顺序及暂停状态持久化，命令有权限、身份与审计；只调整尚未执行项，不能改写已经启动的执行。
- [ ] 暂停不取消运行中任务、不重置排队期限；恢复遵守并发和有效权限，降低槽位等待自然释放。
- [ ] 调序与取消／超期／启动竞争不重复执行，队列页刷新反映实际排序；不引入 cron、周期任务、多节点复杂调度或人工点“模拟下一项”。

## 验证与证据

至少三个真实小任务配合两个槽位，验证暂停、队首、重启及并发竞争。

每票交付可运行命令、最短演示步骤和输入／动作／可观察结果／证据出处。分别记录确定性实验、真实集成及本票适用的浏览器／部署／内容验收；所有验收当前未执行。

## 贯穿本票的边界

- 随本票行为交付权限、关键事实持久化、失败与重复请求处理、所属审计事件及带新鲜度的健康／异常来源。观测出口使用有界字段允许清单。
- 一个 Run 至多一次实际 Agent 执行和一个权威终态；Result、Artifact 可用性和实际回收独立。未知结果先对账，业务重做须新 Run，阶段重试不重置累计限制。
- 页面与 API 查询同一事实；管理操作由服务端授权。提供刷新、越权和错误恢复证据，不以模拟控件或替身结果代替真实路径。
