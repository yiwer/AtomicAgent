# 27 — 从登记 Skills 仓库发现候选并审阅发布

**What to build:** 维护者登记允许的初始 Skills 来源，发现固定候选修订，经审阅发布后由新 Run 选择并使用。

**Blocked by:** 06 — 登记 Skill 并证明任务实际使用

**Status:** ready-for-agent

**范围来源：** A 新增；2026-09-14 用户接受 v0＋A 拆分后发布。

**验收对应：** 原型 A 的已批准管理行为；完整页面及来源责任见票务计划。

**管理台验收对应：** A-AC-08。

## Acceptance criteria

- [ ] 限定已登记可访问仓库，固定内容修订／摘要及入口；不自动执行任意仓库脚本，不使用原型演示地址。
- [ ] 同步仅产生候选，展示变更与影响后再发布；已登记修订及既有 Run 不被同步覆盖或自动注入能力。
- [ ] 来源不可用／内容不完整／入口无效明确失败，可重试发现同一候选且不重复发布；发布后通过普通 Skill 任务验证加载和使用。

## 验证与证据

受控真实仓库的两个固定修订，发现→审阅→发布→执行；断网及漂移反例。

每票交付可运行命令、最短演示步骤和输入／动作／可观察结果／证据出处。分别记录确定性实验、真实集成及本票适用的浏览器／部署／内容验收；所有验收当前未执行。

## 贯穿本票的边界

- 随本票行为交付权限、关键事实持久化、失败与重复请求处理、所属审计事件及带新鲜度的健康／异常来源。观测出口使用有界字段允许清单。
- 一个 Run 至多一次实际 Agent 执行和一个权威终态；Result、Artifact 可用性和实际回收独立。未知结果先对账，业务重做须新 Run，阶段重试不重置累计限制。
- 页面与 API 查询同一事实；管理操作由服务端授权。提供刷新、越权和错误恢复证据，不以模拟控件或替身结果代替真实路径。

## 外部实施输入

需登记、获准访问的实际 Skills 仓库及固定修订。
