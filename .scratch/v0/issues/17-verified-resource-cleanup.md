# 17 — 从回收单重试处置并核验资源消失

**What to build:** 维护者从 A 的 sandbox／回收详情按不可变资源身份请求重试回收，看到删除请求、核验中、失败／未知及真正完成。

**Blocked by:** 09 — 取消任务并核验实际停止；14 — 创建或启动回执丢失时找回既有执行

**Status:** ready-for-agent

**范围来源：** PRD + A；2026-09-14 用户接受 v0＋A 拆分后发布。

**验收对应：** AC-16。

**管理台验收对应：** A-AC-03。

## Acceptance criteria

- [ ] 成功、失败、取消、超时和准备失败所产生的资源都有独立 CleanupObligation，涵盖进程、目录、临时配置／会话、有效凭据能力及归任务所有的暂存。
- [ ] 回收动作可重试且持久化，不能改变业务终态或重跑任务；自动回收与人工请求使用同一责任身份和受控命令。
- [ ] 删除请求成功不等于完成；核验需要目标身份、完整且新鲜的权威观测及时间。权限不足、超时、列表不全保持未知。
- [ ] 展示 5 分钟目标、逾期年龄与处置原因，异常确认不解除回收责任；A 中无手动设置“已删除”的产品按钮。

## 验证与证据

真实删除失败→受控重试→新鲜不存在证据；重启恢复未闭合责任，比较 Result 前后不变。

每票交付可运行命令、最短演示步骤和输入／动作／可观察结果／证据出处。分别记录确定性实验、真实集成及本票适用的浏览器／部署／内容验收；所有验收当前未执行。

## 贯穿本票的边界

- 随本票行为交付权限、关键事实持久化、失败与重复请求处理、所属审计事件及带新鲜度的健康／异常来源。观测出口使用有界字段允许清单。
- 一个 Run 至多一次实际 Agent 执行和一个权威终态；Result、Artifact 可用性和实际回收独立。未知结果先对账，业务重做须新 Run，阶段重试不重置累计限制。
- 页面与 API 查询同一事实；管理操作由服务端授权。提供刷新、越权和错误恢复证据，不以模拟控件或替身结果代替真实路径。
