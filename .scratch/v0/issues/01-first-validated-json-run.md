# 01 — 提交提示词并在 A 中取回已校验 JSON

**What to build:** 调用方提交仅需结构化 JSON 的小任务；平台固定一个登记环境／模型修订，经 OpenSandbox、Claude 执行、平台校验、持久提交及终态回收，维护者在 A 的任务表与详情查看结果。

**Blocked by:** None — can start immediately

**Status:** ready-for-agent

**范围来源：** PRD + A；2026-09-14 用户接受 v0＋A 拆分后发布。

**验收对应：** AC-08、AC-09、AC-23、AC-27。

**管理台验收对应：** A-AC-01。

## Acceptance criteria

- [ ] 只支持一个受控实验 profile 和一个小输出契约；Linux Docker、runtime、SDK／CLI、镜像、model 和服务端 secret 引用必须固定。真实 profile 的用途及工具／schema 兼容性单独取证，失败不得静默换套餐或模型。
- [ ] Run、幂等绑定、固定 ExecutionManifest、最小授权、关键审计及资源归属先可靠保存；一个 Run 至多一个实际 Attempt、一个已提交终态。断开页面后仍可查询，Agent 文本或退出码不能直接裁定成功。
- [ ] A 采用固定分组侧栏、顶部真实身份／工作区、任务列表和详情面板；刷新后数据来自持久事实。业务状态与清理状态独立；正常及准备失败产生的资源均登记回收，确认不存在才完成。
- [ ] 鉴权、业务数据隔离、观测字段允许清单、失败分类和最小执行侧期限从本票开始生效；schema 不合格及缺输入／授权明确失败，不进入人工等待。

## 验证与证据

API 提交→页面刷新取回→实际资源核验；确定性替身覆盖失败契约，真实 profile 完成同一小任务。替身通过不能关闭本票的真实执行验收。

每票交付可运行命令、最短演示步骤和输入／动作／可观察结果／证据出处。分别记录确定性实验、真实集成及本票适用的浏览器／部署／内容验收；当前确定性与 Chromium 验证已有归档，真实部署／模型／内容及人工验收尚未完成，见下方 Comments 和实施入口。

## 贯穿本票的边界

- 随本票行为交付权限、关键事实持久化、失败与重复请求处理、所属审计事件及带新鲜度的健康／异常来源。观测出口使用有界字段允许清单。
- 一个 Run 至多一次实际 Agent 执行和一个权威终态；Result、Artifact 可用性和实际回收独立。未知结果先对账，业务重做须新 Run，阶段重试不重置累计限制。
- 页面与 API 查询同一事实；管理操作由服务端授权。提供刷新、越权和错误恢复证据，不以模拟控件或替身结果代替真实路径。

## 外部实施输入

真实验收需要指定 Linux 实验节点，以及获准的确切模型 profile、endpoint／model 和服务端凭据绑定。可先推进确定性实现；未具备真实条件时保留未验收，不默认换套餐／账户，不为当前拆票读取密钥或调用计费服务。
