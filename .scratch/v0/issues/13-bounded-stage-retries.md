# 13 — 短暂故障只重试当前阶段且受累计预算限制

**What to build:** 暂时性准备或模型故障在同一 Run 的既定阶段有界恢复；调用方看见次数、消耗和耗尽原因，不发生整项 Agent 重跑。

**Blocked by:** 11 — 修改限额并实际限制后续任务；12 — 在任务与额度页查看可信用量

**Status:** ready-for-agent

**范围来源：** PRD + A；2026-09-14 用户接受 v0＋A 拆分后发布。

**验收对应：** AC-08、AC-13。

**管理台验收对应：** A-AC-06。

## Acceptance criteria

- [ ] 明确可重试错误及阶段，每阶段最多追加 2 次；SDK、平台和适配器的嵌套重试纳入同一计数与观测。
- [ ] 期限及累计预算始终从原 Run 延续，未知消费按支持策略处置；耗尽后明确失败／超时并清理。
- [ ] 已执行任务不自动新增 Attempt；不合格输出默认不调用 Agent 修复，缺输入／授权立即失败，不挂起等人。

## 验证与证据

适配器注入 429／短暂准备故障与嵌套重试；验证实际请求数、同一执行身份、累计限制和页面原因。

每票交付可运行命令、最短演示步骤和输入／动作／可观察结果／证据出处。分别记录确定性实验、真实集成及本票适用的浏览器／部署／内容验收；所有验收当前未执行。

## 贯穿本票的边界

- 随本票行为交付权限、关键事实持久化、失败与重复请求处理、所属审计事件及带新鲜度的健康／异常来源。观测出口使用有界字段允许清单。
- 一个 Run 至多一次实际 Agent 执行和一个权威终态；Result、Artifact 可用性和实际回收独立。未知结果先对账，业务重做须新 Run，阶段重试不重置累计限制。
- 页面与 API 查询同一事实；管理操作由服务端授权。提供刷新、越权和错误恢复证据，不以模拟控件或替身结果代替真实路径。
