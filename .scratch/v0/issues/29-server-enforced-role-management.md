# 29 — 调整角色权限并由服务端立即执行

**What to build:** 获授权的权限维护者审阅并修改管理角色能力，新请求按已生效策略获得允许或拒绝，A 与 API 表现一致。

**Blocked by:** 20 — 按独立审计权限查询和导出操作责任

**Status:** ready-for-agent

**范围来源：** A 新增；2026-09-14 用户接受 v0＋A 拆分后发布。

**验收对应：** AC-23。

**管理台验收对应：** A-AC-10。

## Acceptance criteria

- [ ] 真实登录身份绑定服务端授权；业务、健康、审计和强制处置分开。原型右上角随意切角色不进入正式产品。
- [ ] 权限变更有固定策略修订、变更摘要、影响和审计；并发覆盖冲突可查，禁止自助提权，保留至少一个有效管理入口。
- [ ] 已登录会话后续请求遵循新策略，直接 API 和旧页面缓存不能绕过；此变更不自动改写已固定的 Run 清单或替代显式运行授权撤销。

## 验证与证据

多个真实测试身份，授予／收回权限后比较刷新、旧会话和直调 API 的拒绝证据。

每票交付可运行命令、最短演示步骤和输入／动作／可观察结果／证据出处。分别记录确定性实验、真实集成及本票适用的浏览器／部署／内容验收；所有验收当前未执行。

## 贯穿本票的边界

- 随本票行为交付权限、关键事实持久化、失败与重复请求处理、所属审计事件及带新鲜度的健康／异常来源。观测出口使用有界字段允许清单。
- 一个 Run 至多一次实际 Agent 执行和一个权威终态；Result、Artifact 可用性和实际回收独立。未知结果先对账，业务重做须新 Run，阶段重试不重置累计限制。
- 页面与 API 查询同一事实；管理操作由服务端授权。提供刷新、越权和错误恢复证据，不以模拟控件或替身结果代替真实路径。
