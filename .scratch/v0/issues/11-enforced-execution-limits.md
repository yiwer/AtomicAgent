# 11 — 修改限额并实际限制后续任务

**What to build:** 维护者在 A 审阅并发布执行限额，新 Run 按固定限制排队及运行；超期或超限被实际限制／终止并可查原因。

**Blocked by:** 02 — 上传文件并交付可下载的处理结果；05 — 发布环境与模型修订并用于新任务；09 — 取消任务并核验实际停止

**Status:** ready-for-agent

**范围来源：** PRD + A；2026-09-14 用户接受 v0＋A 拆分后发布。

**验收对应：** AC-14。

**管理台验收对应：** A-AC-06。

## Acceptance criteria

- [ ] 默认并发 2、总期限 60 分钟、输入 50 MiB、产物 100 MiB、2 vCPU／4 GiB；参数按登记范围校验并写入清单。
- [ ] 总期限覆盖排队至结果提交；CPU／内存及支持的文件／执行限制在执行层生效，明确限制型与终止型行为，不用配置数字当证据。
- [ ] 降低并发不杀死既有执行，只阻止进一步超额启动；历史清单不改写。控制面与 worker 均失效时仍有独立到期／巡检停止保障。
- [ ] 记录期限与预算终止原因，登记清理；不支持的硬金额约束明确拒绝，不伪装为预警或已强制。

## 验证与证据

提交超过槽位的任务、真实压力／超期任务与全控制面故障；对比有效限制、执行观测和终态。

每票交付可运行命令、最短演示步骤和输入／动作／可观察结果／证据出处。分别记录确定性实验、真实集成及本票适用的浏览器／部署／内容验收；所有验收当前未执行。

## 贯穿本票的边界

- 随本票行为交付权限、关键事实持久化、失败与重复请求处理、所属审计事件及带新鲜度的健康／异常来源。观测出口使用有界字段允许清单。
- 一个 Run 至多一次实际 Agent 执行和一个权威终态；Result、Artifact 可用性和实际回收独立。未知结果先对账，业务重做须新 Run，阶段重试不重置累计限制。
- 页面与 API 查询同一事实；管理操作由服务端授权。提供刷新、越权和错误恢复证据，不以模拟控件或替身结果代替真实路径。
