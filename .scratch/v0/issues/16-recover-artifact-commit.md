# 16 — 上传或提交中断后恢复交付而不重跑

**What to build:** Agent 已生成合格输出后，存储／提交故障只恢复文件转存或结果提交，调用方最终取回一次可靠交付或明确交付失败。

**Blocked by:** 13 — 短暂故障只重试当前阶段且受累计预算限制

**Status:** ready-for-agent

**范围来源：** PRD + A；2026-09-14 用户接受 v0＋A 拆分后发布。

**验收对应：** AC-08、AC-10。

## Acceptance criteria

- [ ] 上传失败、上传已成功但回执丢失、上传后结果提交失败均按稳定对象／提交身份核对恢复。
- [ ] 只恢复相关阶段，遵守追加 2 次及累计期限／预算；不重新调用 Agent、增加 Attempt 或重做研究。
- [ ] 未提交对象始终有归属和回收责任；迟到提交与终态竞争不覆盖结果，半成品不能作为成功 Result 访问。

## 验证与证据

对象存储／事务边界故障注入，真实下载内容核验及 Agent 启动次数核对。

每票交付可运行命令、最短演示步骤和输入／动作／可观察结果／证据出处。分别记录确定性实验、真实集成及本票适用的浏览器／部署／内容验收；所有验收当前未执行。

## 贯穿本票的边界

- 随本票行为交付权限、关键事实持久化、失败与重复请求处理、所属审计事件及带新鲜度的健康／异常来源。观测出口使用有界字段允许清单。
- 一个 Run 至多一次实际 Agent 执行和一个权威终态；Result、Artifact 可用性和实际回收独立。未知结果先对账，业务重做须新 Run，阶段重试不重置累计限制。
- 页面与 API 查询同一事实；管理操作由服务端授权。提供刷新、越权和错误恢复证据，不以模拟控件或替身结果代替真实路径。
