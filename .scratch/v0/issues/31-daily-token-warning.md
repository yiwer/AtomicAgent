# 31 — 达到每日 token 预警阈值后生成可处置异常

**What to build:** 维护者设置每日 token 预警阈值，A 依据可信用量展示已知消耗／未知项并产生一次可处置异常。

**Blocked by:** 12 — 在任务与额度页查看可信用量；24 — 处置异常并依据新鲜证据恢复

**Status:** ready-for-agent

**范围来源：** A 新增；2026-09-14 用户接受 v0＋A 拆分后发布。

**验收对应：** 原型 A 的已批准管理行为；完整页面及来源责任见票务计划。

**管理台验收对应：** A-AC-12。

## Acceptance criteria

- [ ] 明确工作区统计范围、时区和自然日窗口；固定策略版本，区分已知累计、迟到观测和未知覆盖，不使用硬编码模拟数字。
- [ ] 跨阈值触发可去重异常；累计重报与迟到数据不重复加量或刷屏，日界线及策略变更可追溯。
- [ ] 这是预警，不能声称消费硬上限，也不自动重跑／终止任务；处置沿用确认／抑制／恢复生命周期。

## 验证与证据

受控时间跨日、重复／迟到 usage 及未知范围，核对额度页、异常与实际聚合一致。

每票交付可运行命令、最短演示步骤和输入／动作／可观察结果／证据出处。分别记录确定性实验、真实集成及本票适用的浏览器／部署／内容验收；所有验收当前未执行。

## 贯穿本票的边界

- 随本票行为交付权限、关键事实持久化、失败与重复请求处理、所属审计事件及带新鲜度的健康／异常来源。观测出口使用有界字段允许清单。
- 一个 Run 至多一次实际 Agent 执行和一个权威终态；Result、Artifact 可用性和实际回收独立。未知结果先对账，业务重做须新 Run，阶段重试不重置累计限制。
