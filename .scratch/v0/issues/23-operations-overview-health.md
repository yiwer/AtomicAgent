# 23 — 在 A 首页定位真实积压和未知健康

**What to build:** 维护者进入 A 运维总览，按运行与回收指标→待处置异常→任务表查看当前事实，右侧查看依赖健康与最近获授权操作。

**Blocked by:** 01 — 提交提示词并在 A 中取回已校验 JSON

**Status:** ready-for-agent

**范围来源：** PRD + A；2026-09-14 用户接受 v0＋A 拆分后发布。

**验收对应：** AC-24。

**管理台验收对应：** A-AC-01、A-AC-04。

## Acceptance criteria

- [ ] 健康事实带来源、观测时间和覆盖范围；进程存活、可接纳、空闲、零资源、采集失联／列表不完整分别展示。
- [ ] 从权威状态和实际 provider 观测统计任务／在途年龄／阶段／worker／sandbox；随能力落地接入模型／MCP、用量、存储、回收和观测链，不预填不存在的数据。
- [ ] 成功率显示样本和分类，总耗时含排队到提交，清理耗时单列；清理达标分母包含逾期未完成者，SSE 重放不重复计数，无界 ID 不作指标标签。
- [ ] 各卡片可进入相应详情；无审计权限的用户看不到最近审计操作，未知状态不能显示为正常，刷新和无数据场景可用。

## 验证与证据

构造运行／卡住／终态混合任务，注入过期观测与不完整资源列表；API、真实清单与浏览器首页相互核对。

每票交付可运行命令、最短演示步骤和输入／动作／可观察结果／证据出处。分别记录确定性实验、真实集成及本票适用的浏览器／部署／内容验收；所有验收当前未执行。

## 贯穿本票的边界

- 随本票行为交付权限、关键事实持久化、失败与重复请求处理、所属审计事件及带新鲜度的健康／异常来源。观测出口使用有界字段允许清单。
- 一个 Run 至多一次实际 Agent 执行和一个权威终态；Result、Artifact 可用性和实际回收独立。未知结果先对账，业务重做须新 Run，阶段重试不重置累计限制。
- 页面与 API 查询同一事实；管理操作由服务端授权。提供刷新、越权和错误恢复证据，不以模拟控件或替身结果代替真实路径。
