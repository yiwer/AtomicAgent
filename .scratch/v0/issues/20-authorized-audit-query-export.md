# 20 — 按独立审计权限查询和导出操作责任

**What to build:** 审计读取者在 A 按时间、Run、主体、动作和目标筛选、分页及限额导出可信操作记录，健康读取者无法读取审计或业务正文。

**Blocked by:** 01 — 提交提示词并在 A 中取回已校验 JSON

**Status:** ready-for-agent

**范围来源：** PRD + A；2026-09-14 用户接受 v0＋A 拆分后发布。

**验收对应：** AC-09、AC-19、AC-23。

**管理台验收对应：** A-AC-05。

## Acceptance criteria

- [ ] 审计主体来自受控身份，区分意图、拒绝、已观测成功／失败、未知和延迟补记；Agent 自报 actor／success 不能伪造权威记录。
- [ ] 稳定分页及限额导出；查询／导出本身留痕一次，不递归记录；运行账号只能追加纠正事实，到期删除走独立留存责任。
- [ ] 审计读取、健康读取、业务数据读取、强制处置分别在服务端鉴权；跨身份、元数据／trace 旁路及合成 secret／签名 URL／恶意错误均验证。
- [ ] 本票建立查询／导出纵向路径；后续每个功能必须同步接入所属 A-01–08 审计事件，不能等待最终票补日志。

## 验证与证据

多身份 API／浏览器验收，拒绝与未知记录检索、分页稳定性和有界导出／脱敏检查。

每票交付可运行命令、最短演示步骤和输入／动作／可观察结果／证据出处。分别记录确定性实验、真实集成及本票适用的浏览器／部署／内容验收；所有验收当前未执行。

## 贯穿本票的边界

- 随本票行为交付权限、关键事实持久化、失败与重复请求处理、所属审计事件及带新鲜度的健康／异常来源。观测出口使用有界字段允许清单。
- 一个 Run 至多一次实际 Agent 执行和一个权威终态；Result、Artifact 可用性和实际回收独立。未知结果先对账，业务重做须新 Run，阶段重试不重置累计限制。
- 页面与 API 查询同一事实；管理操作由服务端授权。提供刷新、越权和错误恢复证据，不以模拟控件或替身结果代替真实路径。
