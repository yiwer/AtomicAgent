# 32 — 在选定 Linux 部署边界复验两类工作负载

**What to build:** 维护者在固定 Linux 节点运行两类真实任务，比较 Docker 与 gVisor 的行为及隔离结果，取得可复现的执行和回收部署方案。

**Blocked by:** 10 — 让恶意任务在隔离与只读边界内失败；11 — 修改限额并实际限制后续任务；15 — worker 失联后安全接管同一执行或停止失败；21 — 核心记录故障时停止新工作但仍可停止与回收

**Status:** ready-for-agent

**范围来源：** PRD 部署交付；2026-09-14 用户接受 v0＋A 拆分后发布。

**验收对应：** AC-27。

## Acceptance criteria

- [ ] 记录确切 OpenSandbox、SDK／CLI、镜像、节点、获准 model profile 与能力覆盖；两类任务在实际部署路径完成交付和清理。
- [ ] Docker 与 gVisor 使用同工作负载检验文件／网络边界、工具循环、取消、资源限制、控制面故障和回收；不以 Docker 结果替代 gVisor。
- [ ] gVisor 可以评估不通过或不适用，但必须给出证据及实际采用边界；无未指定节点的自动部署授权，也不预填强隔离通过。

## 验证与证据

版本固定的部署命令、两类 API 样例、实际资源证据与分 backend 比较；属于可运行部署交付，问题回到责任票修复。

每票交付可运行命令、最短演示步骤和输入／动作／可观察结果／证据出处。分别记录确定性实验、真实集成及本票适用的浏览器／部署／内容验收；所有验收当前未执行。

## 贯穿本票的边界

- 随本票行为交付权限、关键事实持久化、失败与重复请求处理、所属审计事件及带新鲜度的健康／异常来源。观测出口使用有界字段允许清单。
- 一个 Run 至多一次实际 Agent 执行和一个权威终态；Result、Artifact 可用性和实际回收独立。未知结果先对账，业务重做须新 Run，阶段重试不重置累计限制。
- 页面与 API 查询同一事实；管理操作由服务端授权。提供刷新、越权和错误恢复证据，不以模拟控件或替身结果代替真实路径。

## 外部实施输入

需指定 Linux 节点、版本固定的部署配置和可评估的隔离运行方式；部署与模型调用授权在实施时核对。
