# 10 — 让恶意任务在隔离与只读边界内失败

**What to build:** 文件或研究输入试图越界时，平台实际阻断并返回受控失败，A 展示可核对原因；后续任务仍获得干净执行空间。

**Blocked by:** 07 — 通过登记只读 MCP 交付研究报告

**Status:** ready-for-agent

**范围来源：** PRD + A；2026-09-14 用户接受 v0＋A 拆分后发布。

**验收对应：** AC-04、AC-15。

## Acceptance criteria

- [ ] 在工具、凭据、文件和网络边界联合执行只读／任务工作区策略；覆盖路径与符号链接越界、重定向、不允许目的地和外部写。
- [ ] A 写标记及启动子进程后，B 不继承文件、进程、配置、凭据或会话；终态后不能发起新的任务动作。
- [ ] 对绕过受控工具的 shell／网络路径实际验证；审计无法覆盖的路径标 partial／unknown，要求完整覆盖的配置不被虚假接纳。

## 验证与证据

两个真实 Run 的污染反例、受控外部写接收端与网络／文件观测；Docker 的此结果不冒称 gVisor 强隔离。

每票交付可运行命令、最短演示步骤和输入／动作／可观察结果／证据出处。分别记录确定性实验、真实集成及本票适用的浏览器／部署／内容验收；所有验收当前未执行。

## 贯穿本票的边界

- 随本票行为交付权限、关键事实持久化、失败与重复请求处理、所属审计事件及带新鲜度的健康／异常来源。观测出口使用有界字段允许清单。
- 一个 Run 至多一次实际 Agent 执行和一个权威终态；Result、Artifact 可用性和实际回收独立。未知结果先对账，业务重做须新 Run，阶段重试不重置累计限制。
- 页面与 API 查询同一事实；管理操作由服务端授权。提供刷新、越权和错误恢复证据，不以模拟控件或替身结果代替真实路径。
