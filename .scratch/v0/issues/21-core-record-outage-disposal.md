# 21 — 核心记录故障时停止新工作但仍可停止与回收

**What to build:** 关键存储不可写时，A 明示退化并阻止新接纳、授权和执行；维护者仍能使用受限保底路径停止及回收既有资源。

**Blocked by:** 17 — 从回收单重试处置并核验资源消失；20 — 按独立审计权限查询和导出操作责任

**Status:** ready-for-agent

**范围来源：** PRD + A；2026-09-14 用户接受 v0＋A 拆分后发布。

**验收对应：** AC-21。

**管理台验收对应：** A-AC-04。

## Acceptance criteria

- [ ] 真实写入失败时不返回虚假接受／成功提交，不放行无法记录的新能力；可用时采用有界持久应急记录，否则停止并标未知。
- [ ] 停止／回收不因审计出口故障永久堵塞；保底路径限定权限、资源身份及动作，不开放宿主 shell。
- [ ] 恢复后按实际资源与操作身份对账补记，保留原发生时间、补记时间及覆盖缺口；不重跑 Agent，不把页面按钮禁用当服务端拒绝证据。

## 验证与证据

切断关键持久存储，API 越过页面直接提交／授权／启动均拒绝；已有执行真实停止回收，恢复后查补记。

每票交付可运行命令、最短演示步骤和输入／动作／可观察结果／证据出处。分别记录确定性实验、真实集成及本票适用的浏览器／部署／内容验收；所有验收当前未执行。

## 贯穿本票的边界

- 随本票行为交付权限、关键事实持久化、失败与重复请求处理、所属审计事件及带新鲜度的健康／异常来源。观测出口使用有界字段允许清单。
- 一个 Run 至多一次实际 Agent 执行和一个权威终态；Result、Artifact 可用性和实际回收独立。未知结果先对账，业务重做须新 Run，阶段重试不重置累计限制。
- 页面与 API 查询同一事实；管理操作由服务端授权。提供刷新、越权和错误恢复证据，不以模拟控件或替身结果代替真实路径。
