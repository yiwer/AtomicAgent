# 14 — 创建或启动回执丢失时找回既有执行

**What to build:** sandbox 创建或 Agent 启动响应丢失后，平台用稳定身份对账，A 呈现实际资源与执行观测，避免重复执行及无主资源。

**Blocked by:** 01 — 提交提示词并在 A 中取回已校验 JSON

**Status:** ready-for-agent

**范围来源：** PRD + A；2026-09-14 用户接受 v0＋A 拆分后发布。

**验收对应：** AC-11。

**管理台验收对应：** A-AC-03。

## Acceptance criteria

- [ ] 创建和启动意图先持久保存，关联稳定操作／资源／执行身份；provider 身份尚未知也保留可对账责任。
- [ ] 结果未知先核验既有操作，不把未知当未创建／未启动；重试不产生第二个实际 Agent。
- [ ] 无法确定的资源保持未知与回收责任，资源列表不完整／无权限不是确认不存在；平台重启后仍可继续对账。

## 验证与证据

在 provider 已产生副作用后丢弃响应；核对实际资源、启动计数与 A 资源详情，注入查询失败。

每票交付可运行命令、最短演示步骤和输入／动作／可观察结果／证据出处。分别记录确定性实验、真实集成及本票适用的浏览器／部署／内容验收；所有验收当前未执行。

## 贯穿本票的边界

- 随本票行为交付权限、关键事实持久化、失败与重复请求处理、所属审计事件及带新鲜度的健康／异常来源。观测出口使用有界字段允许清单。
- 一个 Run 至多一次实际 Agent 执行和一个权威终态；Result、Artifact 可用性和实际回收独立。未知结果先对账，业务重做须新 Run，阶段重试不重置累计限制。
- 页面与 API 查询同一事实；管理操作由服务端授权。提供刷新、越权和错误恢复证据，不以模拟控件或替身结果代替真实路径。
