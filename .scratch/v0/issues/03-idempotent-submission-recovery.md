# 03 — 提交响应丢失后找回同一 Run

**What to build:** 调用后端并发重传或丢失接受响应后，以原幂等键找回原 Run；A 中始终只出现一个逻辑任务。

**Blocked by:** 01 — 提交提示词并在 A 中取回已校验 JSON

**Status:** ready-for-agent

**范围来源：** PRD + A；2026-09-14 用户接受 v0＋A 拆分后发布。

**验收对应：** AC-05。

**管理台验收对应：** A-AC-01。

## Acceptance criteria

- [ ] 同调用身份、同 key、同执行相关内容返回同一 Run；同 key、不同内容冲突；不同调用身份分别隔离。
- [ ] 接纳事务和响应之间断连、并发提交及服务恢复不重复接纳／启动；已失败或文件过期的 Run 在记录窗口内仍可找回。
- [ ] 提交摘要与执行清单摘要分开；找回旧提交不重新取可变内容或解析当前默认配置。新 key 才表达新业务执行，超出记录窗口不承诺旧保证。

## 验证与证据

通过 API 并发与接受后断网实验，核对 Run／Attempt／真实启动计数；记录去重、冲突及访问审计。

每票交付可运行命令、最短演示步骤和输入／动作／可观察结果／证据出处。分别记录确定性实验、真实集成及本票适用的浏览器／部署／内容验收；所有验收当前未执行。

## 贯穿本票的边界

- 随本票行为交付权限、关键事实持久化、失败与重复请求处理、所属审计事件及带新鲜度的健康／异常来源。观测出口使用有界字段允许清单。
- 一个 Run 至多一次实际 Agent 执行和一个权威终态；Result、Artifact 可用性和实际回收独立。未知结果先对账，业务重做须新 Run，阶段重试不重置累计限制。
- 页面与 API 查询同一事实；管理操作由服务端授权。提供刷新、越权和错误恢复证据，不以模拟控件或替身结果代替真实路径。
