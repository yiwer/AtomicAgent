# 15 — worker 失联后安全接管同一执行或停止失败

**What to build:** worker 失联时维护者看到控制权及既有执行的核验结果；平台安全接管观察同一执行，不能接管则停止并明确失败。

**Blocked by:** 09 — 取消任务并核验实际停止；14 — 创建或启动回执丢失时找回既有执行

**Status:** ready-for-agent

**范围来源：** PRD + A；2026-09-14 用户接受 v0＋A 拆分后发布。

**验收对应：** AC-12。

**管理台验收对应：** A-AC-03。

## Acceptance criteria

- [ ] 接管前核验既有执行并隔离旧控制者；旧 worker 必须不能继续控制资源、发放调用或提交结果。
- [ ] 安全接管不产生第二 Attempt；不安全时终止原执行，保持执行失联原因与独立回收状态，不重新跑业务。
- [ ] 旧 worker 恢复、迟到结果和重复接管不能覆盖权威状态；控制权冲突、观测时间和证据缺口可查询。

## 验证与证据

杀死／隔离 worker 后使旧 worker 恢复；真实检查旧控制被拒、Agent 数量及接管／失败两条路径。

每票交付可运行命令、最短演示步骤和输入／动作／可观察结果／证据出处。分别记录确定性实验、真实集成及本票适用的浏览器／部署／内容验收；所有验收当前未执行。

## 贯穿本票的边界

- 随本票行为交付权限、关键事实持久化、失败与重复请求处理、所属审计事件及带新鲜度的健康／异常来源。观测出口使用有界字段允许清单。
- 一个 Run 至多一次实际 Agent 执行和一个权威终态；Result、Artifact 可用性和实际回收独立。未知结果先对账，业务重做须新 Run，阶段重试不重置累计限制。
- 页面与 API 查询同一事实；管理操作由服务端授权。提供刷新、越权和错误恢复证据，不以模拟控件或替身结果代替真实路径。
