# 25 — 通知异常并独立发现观测链失联

**What to build:** 维护者为异常配置责任者与一个通知通道，A 显示通知去重、重试、失败及通道回执；独立探测能发现采集器和通知链自身中断。

**Blocked by:** 24 — 处置异常并依据新鲜证据恢复

**Status:** ready-for-agent

**范围来源：** PRD + A；2026-09-14 用户接受 v0＋A 拆分后发布。

**验收对应：** AC-26。

**管理台验收对应：** A-AC-04。

## Acceptance criteria

- [ ] 受控接收端先验证稳定通知身份、重复投递、重试及失败；确认、通知被接受和人已阅读分别表达。
- [ ] 观测链自身故障由独立于故障 worker／collector／通知执行器的路径发现，不依赖同一失效通道自报健康。
- [ ] 部署时绑定实际获准通道和接收责任者，取得端到端试发回执及恢复证据；未配置或未获发送授权保留真实通道验收未完成，不冒称送达。

## 验证与证据

故障接收端＋链路停机实验；另列获授权部署通道投递证据，A 可查每次结果。

每票交付可运行命令、最短演示步骤和输入／动作／可观察结果／证据出处。分别记录确定性实验、真实集成及本票适用的浏览器／部署／内容验收；所有验收当前未执行。

## 贯穿本票的边界

- 随本票行为交付权限、关键事实持久化、失败与重复请求处理、所属审计事件及带新鲜度的健康／异常来源。观测出口使用有界字段允许清单。
- 一个 Run 至多一次实际 Agent 执行和一个权威终态；Result、Artifact 可用性和实际回收独立。未知结果先对账，业务重做须新 Run，阶段重试不重置累计限制。
- 页面与 API 查询同一事实；管理操作由服务端授权。提供刷新、越权和错误恢复证据，不以模拟控件或替身结果代替真实路径。

## 外部实施输入

需配置接收责任者、实际通道并取得试发授权；受控接收端通过不代替真实通知投递。
