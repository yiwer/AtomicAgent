# 24 — 处置异常并依据新鲜证据恢复

**What to build:** 回收逾期等异常进入 A 待处置列表，维护者接手、限时抑制和执行处置，只有新鲜恢复证据才解除异常。

**Blocked by:** 17 — 从回收单重试处置并核验资源消失；23 — 在 A 首页定位真实积压和未知健康

**Status:** ready-for-agent

**范围来源：** PRD + A；2026-09-14 用户接受 v0＋A 拆分后发布。

**验收对应：** AC-16、AC-25。

**管理台验收对应：** A-AC-04。

## Acceptance criteria

- [ ] 首个纵向场景为真实回收逾期；记录触发证据、责任者、资源、处置步骤及独立的确认／抑制／恢复状态。
- [ ] 确认不恢复；抑制需要操作者、原因和期限，过期自动解除，抑制期间底层清理持续；采集失联保持未知且不能自动消警。
- [ ] 建立 AL-01–08 统一生命周期；已落地来源立即接入，其余来源由所属票补齐并附故障证据，发布前八类均能触发、定位和核验恢复。

## 验证与证据

受控时钟与真实回收失败，从首页→接手→抑制到期→实际回收→新鲜观测闭环；其他来源按覆盖表验收。

每票交付可运行命令、最短演示步骤和输入／动作／可观察结果／证据出处。分别记录确定性实验、真实集成及本票适用的浏览器／部署／内容验收；所有验收当前未执行。

## 贯穿本票的边界

- 随本票行为交付权限、关键事实持久化、失败与重复请求处理、所属审计事件及带新鲜度的健康／异常来源。观测出口使用有界字段允许清单。
- 一个 Run 至多一次实际 Agent 执行和一个权威终态；Result、Artifact 可用性和实际回收独立。未知结果先对账，业务重做须新 Run，阶段重试不重置累计限制。
- 页面与 API 查询同一事实；管理操作由服务端授权。提供刷新、越权和错误恢复证据，不以模拟控件或替身结果代替真实路径。
